# 分析者間の一致度（Krippendorff の α）を出す

Ahnotation の評価から，分析者間の一致度を Krippendorff の α で出す．この skill の立場は，設定を聞き取るだけの係ではない．実験の設計を読み，「この設計ならこの分析がよい」と理由をつけて勧める係である．利用者が勧めを受け入れるか直すだけで済むようにする．

計算は `tools/alpha/alpha.js`（本体は `core/alpha.js`）が行う．リポジトリの中で使うならリポジトリの直下のものを使う．無ければ（claude.ai で使うとき）この skill のフォルダの中の `ahnotation/` にあるものを使う．`npm run alpha -- <実験フォルダ> …` の代わりに `node ahnotation/tools/alpha/alpha.js <実験フォルダ> …` を実行する．スクリプトの細かい仕様は README の「結果の回収」の節の「一致度」の項にある．

## α の定義（説明に使う）

- **時間連続の評価として出す**：単位は動画の 1 フレーム（1/60 秒），評定者は分析者である．時間の各瞬間を単位とし，その瞬間に分析者どうしの値がどれだけ一致したかを測る．区間ごとの方式（Excel・SAM など）も，区間の値を時間に広げて同じ計算に乗せる．このため，区間ごとの方式と連続の方式（スライダー・ジョイスティック）を同じ物差しで比べられる．
- **欠損にするもの**：
  - 評価区間の外
  - 区間ごとの方式の 0（発声なし）．感情の値の一致だけを測るためで，発声があったかどうかの判断のずれは α に入らない
  - 連続の方式で，最初に動かすまでの初期値．動かしていない時間は判断していないため
- **対象外の方式**：PANAS，RankTrace（上下限が無い），変化の時点を押す方式（変化ボタン・AffectRank・カスタムの 8 方向）は除く．`problems.txt` に書かれる．
- 軸は分析者が答えた軸（`valence`・`arousal`，PANA なら `pa`・`na` など）ごとに出す．軸を回した方式では，VA に直した `va_valence`・`va_arousal` の行も出る．

## 手順

### 1. 実験フォルダを確かめる

利用者に実験フォルダの場所を聞く（会話に出ていれば聞かない）．`データ/<参加者>/annotator/` に zip が無ければ，回収ツールの `1_結果を集める.bat` を先に実行するよう伝えて止める．スクリプトは参加者ごとの zip を直接読むので，`2_全員終わったら_表にまとめる.bat` は要らない．

### 2. 設計を読む

次を読み，下の表の項目を読み取る．

- `experiment.json`：`participants` の試行（`mode`，`video`，`condition`，`practice`），`conditions`
- `データ/<参加者>/annotator/*.zip`：実際に揃ったデータ．zip の中の `*_session.json` の `meta.experiment`（`name`，`participant`，`trial`，`condition`，`practice`）と `meta.mode`・`meta.video_file` を読む．zip の一覧と中身は `node -e` で `tools/collect/lib.js` の `readTrialZip` を使って読める．`experiment.json` と食い違えば，データの方を正とし，食い違いを伝える
- `experiment.json` が無ければ zip だけから読み取り，読み取った設計を利用者に見せて確かめる
- 実験名（`meta.experiment.name`）が 2 つ以上あれば，出力は `データ/一致度/<実験名>/` に分かれる

| 読み取ること | 使い道 |
|---|---|
| 条件の数と，各条件の方式 | まとめ方 |
| 各方式が区間ごとか連続か，整数か小数か | 尺度 |
| 練習を除いた動画の本数（条件ごと） | 信頼区間が出せるか |
| 条件×動画ごとの分析者の人数 | 人数の偏りの注意 |
| 分析者が全条件を評価したか（参加者内）か，一部だけか（参加者間） | 比べ方の注意 |
| 対象外の方式が混ざっているか | 先に伝える |
| 同じ動画を 2 人以上が評価しているか | 各自が別の動画を評価する設計（発声者が自分の録画を回顧評価するなど）では α を出せない．その場合は回さずにそう伝え，同じ動画を複数の分析者に評価してもらう設計が要ることを説明する |

条件名（`condition`）が空の試行は，方式（`method`）が条件名になる．

方式の性質：連続で小数（`feeltrace`，`emujoy`，`rcea`，`darma`，`throttle`，`halolight`，`carma`），連続で整数（`key`），区間ごとで整数（`excel`，`sam`，`affectgrid`）．`custom` は `options` で決まる（`time: disc` なら区間ごと）．区間ごとの方式でも，区間内の変化（曲線）を使えば小数になる．

### 3. 分析を勧める

読み取った設計を短く示し，続けて勧めを理由つきで出す．聞くのは設計から決まらないことだけにする．

- **まとめ方（`--by`）**
  - 条件が 2 つ以上：条件どうしの比較として `condition` を主に勧める．どの動画で一致が崩れたかを見るために `video` もあわせて出す（`--by condition,video`）
  - 条件が 1 つ：信頼性の報告として `condition` と `video` の両方を出す
  - 比較か報告かが設計から読めない（条件が 2 つ以上あるが，方式の比較が目的か分からない）ときだけ，α を何に使うかを聞く
- **尺度（`--scale`）**：既定は間隔（`interval`）．1〜9 の評価は間隔とみなすのが通例である．全条件が整数で答える方式なら，順序（`ordinal`）も候補として示す．順序は値の間隔を等しいとみなさないが，間隔と値がずれたときに読み方が難しくなる．小数の方式が 1 つでも混ざれば間隔にそろえる．尺度は全条件で 1 つにする（同じ物差しで比べるため）
- **信頼区間（`--boot`）**：既定の 1000 回で出す．条件ごとの区間は動画を単位に再標本化するので，動画が 5 本未満の条件では出ない．そのときは先に伝え，動画ごとの区間（数秒の塊を単位にする．`--block`，既定 5 秒）で代えられることを示す．`--block` は，評価の値がそれより長くは引きずられないと考えられる長さにする．5 秒より短い動画が多ければ短くする
- **人数の偏り**：条件×動画ごとの分析者の人数が条件で大きく違えば，比べる前にそのことを伝える．参加者間の設計なら，α の違いには分析者の違いも混ざることを伝える

勧めを受け入れられたら，4 へ進む．直されたら，直した設定で進む．

### 4. 回す

```
npm run alpha -- <実験フォルダ> --by condition,video --scale interval --boot 1000 --block 5 --seed 1
```

出力は `<実験フォルダ>/データ/一致度/<実験名>/` の `alpha.csv`，`settings.txt`，`problems.txt` である．毎回作り直す．`alpha.csv` の列：`by`，`condition`，`video`（`by=condition` では空），`axis`，`scale`，`alpha`，`ci_low`・`ci_high`（95% 区間．出さなければ空），`n_raters`，`n_units`（値が 2 人分以上あるフレームの数），`n_values`，`n_clusters`（再標本化の塊の数），`n_boot`．

### 5. 結果を返す

- `alpha.csv` を表で示す．条件ごとの行を先に，動画ごとの行は α の低い順に並べて示す
- **読み方**
  - 目安：Krippendorff（2004）は，確かな結論には α ≥ .800，暫定的な結論にも α ≥ .667 を求める．ただし，時間連続の感情評価ではこれより低く出るのが普通である．目安は参考として示し，判定には使わない
  - 条件どうしの比較は，点の値ではなく信頼区間の重なりで見る．重なりが大きければ「差があるとは言えない」と伝える
  - 反応の遅れ（人によって 0.5〜2 秒）も不一致に数えられるので，連続の方式の α は低めに出やすい．区間ごとの方式は区間の中で値を揃えるので，この影響を受けにくい．方式を比べるときはこの点を添える
  - 0（発声なし）を欠損にしているので，発声の有無の判断の一致は α に入っていない
- `problems.txt` の中身を伝える（除いた試行，2 回評価した組，信頼区間を出さなかった理由，一度も動かさなかった軸）
- **方法の節の下書き**：単位，評定者，欠損の扱い，尺度，まとめ方，信頼区間の作り方を，`settings.txt` の値で 1 段落に書く．例：「分析者間の一致度として Krippendorff の α（間隔尺度）を求めた．単位は動画の 1 フレーム（1/60 秒）とし，評価区間の外，発声なしと評価された区間，評定を始める前の初期値は欠損とした．α は条件ごとに全動画をまとめて求め，95% 信頼区間は動画を単位とするブートストラップ（1000 回，百分位法）で求めた．」

## 注意

- 参加者のデータ（`データ/` の中身）を git に入れない．出力もリポジトリの外の実験フォルダに書く
- 手元の PC のパスや個人の ID を，この skill や出力の説明に書き残さない
