# 評価の説明の書き方（共通）

参加者が快度・覚醒度を評価する実験では，台本に評価の説明を入れる．分析者側（第三者評価）と，回顧評価がある発声者側（本人が自分の録画を評価する）の両方で使う．役割で違うのは「何を基準に評価するか」（下の「教示」）だけで，ほかの部品は共通である．

## 部品と順

1. 評価軸（覚醒度・快度）
2. 評価方法（何を見て，どの単位で，どこに記録するか）
3. 道具の説明
4. 注意事項（評価の規則）
5. 質問を聞く
6. 評価の練習
7. 本番の評価
8. 条件ごとのアンケート（あれば）

1〜5 は実験の説明の章に置く．6〜8 は，分析者側なら条件ごとの節に，発声者側なら練習のプレイと本番の各プレイの直後に置く．

## 教示（役割で変える所）

| | 分析者側 | 発声者側（回顧評価） |
|---|---|---|
| 何を答えるか | 声（と画面）から発声者の感情を推定する | そのときの自分の感情を振り返って答える |
| 評価軸の 1・5・9 の言い方 | `full-template.txt` のまま（「非常に眠そうで」など，見た様子の言い方） | 「そう」を外し，自分の状態の言い方にする（「非常に眠く」「非常に不快で」） |
| `full-template.txt` の「声の強さやトーンに注目します」と例文 | 残す | 使わない（声の聞こえ方ではなく，自分が感じたことを答えるため） |
| 評価方法の台詞の主語 | 「動画内の音声やゲーム画面を元に」 | 「ご自身のプレイの録画を見ながら，そのときの気持ちを思い出して」 |

基準音声（快度 5・覚醒度 5 の「あ」）を評価の基準にするかは，分析者側では `full-template.txt` のとおり基準にする．発声者側では，設計で決まっていれば台詞にし，決まっていなければ `[[◯◯◯]]` にする．

## 道具の説明

- 台詞で全部を説明しない．台詞は「何を入れるか」と 2〜3 個の基本操作までにし，残りは `[* 練習で画面を指しながら見せる]` とする．キーの一覧は台詞にしない．
- annotator を使うなら，方式の名前と入れ方は annotator のリポジトリ直下の `README.md` で確かめる．確かめられなければ `[[◯◯◯]]` にする．
- 条件が複数なら，条件ごとの節を 1 つずつ書き，節の頭の台詞は順番に関係しない形（「次は◯◯方式で評価していただきます」）にする．順番を表す台詞を 2 通り並べない．順序が参加者ごとに違うなら，節の頭のメモに「参加者の順に節を選んで読む」と書く．annotator の実験モードを使うなら，条件名は `experiment.json` の条件名にそろえる（`experiment.json` は `experiment-config` skill が作る）．

## 注意事項（評価の規則）

- `full-template.txt` の分析者側の注意事項（1〜9 をすべて使う必要はない，同じ数字を何度使ってもよい，など）は，今回の設計と合うものだけを残す．
- 次の 4 つは，設計で決まっている形だけを台詞にする．決まっていなければ `[[◯◯◯]]` にして報告で聞く．
  - 1 区間に複数の感情があるとき
  - 迷ったとき
  - 巻き戻してよいか
  - 発声の無い区間

## 練習とアンケート

- 練習は短い区間（10 秒程度）にする．分析者側は `full-template.txt` のとおりお手本動画の最初の部分，発声者側は練習のプレイの録画の最初の部分を使う．
- アンケートを annotator の `survey` で開くなら，台詞は「評価を終えると画面にアンケートのボタンが出るので、答えてください」にし，リンクは書かない．
