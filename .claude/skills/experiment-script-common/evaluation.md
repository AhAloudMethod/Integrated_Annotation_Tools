# 評価の説明の書き方（共通）

参加者が快度・覚醒度を評価する実験では，台本に評価の説明を入れる．分析者側（第三者評価）と，回顧評価がある発声者側（本人が自分の録画を評価する）の両方で使う．役割で違うのは「何を基準に評価するか」（下の「教示」）だけで，ほかの部品は共通である．

## 部品と順

1. 評価軸（快度・覚醒度）
2. 評価方法（何を見て，どの単位で，どこに記録するか）
3. 道具の説明
4. 注意事項（評価の規則）
5. 質問を聞く
6. 評価の練習
7. 本番の評価
8. 試行ごとのアンケート（あれば）
9. 評価についてのインタビュー（あれば）

1〜5 は実験の説明の章に置く．6〜9 は，分析者側なら条件ごとの節に，発声者側なら練習のプレイと本番の各プレイの直後に置く．

## 教示（役割で変える所）

| | 分析者側 | 発声者側（回顧評価） |
|---|---|---|
| 何を答えるか | 声（と画面）から発声者の感情を推定する | そのとき発声に表現しようとした感情を振り返って答える（11/5 に決定．「感じていた感情」と「声の聞こえ方」の中間で，本人の感情に結び付き，音響とも対応しやすい） |
| 評価軸の説明 | `template.txt` の部品「快度と覚醒度の説明」のまま | 同じ部品から「具体的には、声の〜」の 3 行を外す（声の聞こえ方ではなく，発声に表現しようとした感情を答えるため） |
| 評価方法の台詞の主語 | 「動画内の音声やゲーム画面を元に」 | 「ご自身のプレイの録画を見ながら，そのとき発声に表現しようとした感情を思い出して」 |

発声者側の教示は「発声に表現しようとした感情」を既定にする．ただし，発声なし条件（プレイ中に声を出さない条件）と比べる実験では，発声なし条件で「表現しようとした」が成り立たない．そのような実験では，全条件で「そのとき感じていた感情」を答えてもらう形を選んでよい．条件のあいだで教示を変えると比べられなくなるので，選んだ形を全条件で使う．どちらにするかは書く前にユーザに聞く．「感じていた感情」にするなら，評価方法の台詞を「ご自身のプレイの録画を見ながら、そのとき感じていた気持ちを思い出して」にし，注意事項に「声の聞こえ方ではなく、そのときご自身が感じていた気持ちを答えてください。」を足す．

軸は快度，覚醒度の順に説明する．annotator の表示（表の上の行が快度）と書き出しの順に合わせるためである．「快度と覚醒度」のように 2 つの軸を並べて言う台詞も，この順にする．

基準音声（快度 5・覚醒度 5 の「あ」）は，どちらの役割でも評価の基準にする．分析者側は `roles.txt` の評価方法の文面を使う．発声者側は評価方法の節に「基準音声を評価の基準としてください。」と書く．

## 道具の説明

- 台詞は「何を入れるか」と，評価の規則に関わる基本操作（区間の区切り方，区間の中の変化の入れ方，終え方など）までにする．キーの一覧や細かい操作は台詞にしない．
- 台詞に入れない操作は，別紙を見せながら説明する．annotator で，その方式の 1 枚の手順書（リポジトリ直下の `evaluator-quick-<方式>.html`．自分で区切る Excel なら `evaluator-quick-excel.html`）があればそれを使い，台詞の前に `[* 評価のかんたん手順（annotator の evaluator-quick-<方式>.html）を見せながら説明する]` を置く．手順書が無ければ全機能のマニュアル `evaluator-manual.html`（「評価ツールの使い方」）を使い，`[* 評価ツールの使い方のマニュアルを見せながら説明する]` とする．手順書は annotator-guide skill で作れる．練習では `[* 練習で画面を指しながら見せる]` とする．別紙を使わない実験なら，報告で確かめて動作の行を外す．
- 区間の中の変化を入れられる方式（annotator の Excel で `curve: "on"`）では，基本は自分の区切りと区間ごとの一定の値で評価し，変化の激しい部分にだけ使うよう台詞で伝える．例：「基本的には「なぞって評価する」は使わないで、変化の激しい部分にだけ使うようにしてください。」
- annotator を使うなら，方式の名前と入れ方は annotator のリポジトリ直下の `README.md` で確かめる．確かめられなければ `[[◯◯◯]]` にする．
- 条件が複数なら，条件ごとの節を 1 つずつ書き，節の頭の台詞は順番に関係しない形（「次は◯◯方式で評価していただきます」）にする．順番を表す台詞を 2 通り並べない．順序が参加者ごとに違うなら，節の頭のメモに「参加者の順に節を選んで読む」と書く．annotator の実験モードを使うなら，条件名は `experiment.json` の条件名にそろえる（`experiment.json` は `experiment-config` skill が作る）．

## 注意事項（評価の規則）

- `roles.txt` の分析者側の注意事項（1〜9 をすべて使う必要はない，同じ数字を何度使ってもよい，など）は，今回の設計と合うものだけを残す．
- 次の 3 つは決まった文面を使う．分析者側の `roles.txt` の `〔evaluation.md：…〕` の行にも入れる．迷ったときと 1 区間に複数の感情の文面は，守られにくいので `[* ]` で囲んで強調する．設計が違うときだけ書き換える．
  - 迷ったとき：「数値判断に迷った際は、中間の値を取るのではなく、ちゃんと1つの評価に決めてください。」備考欄がある道具（スプレッドシートなど）で迷った理由を書いてもらうなら，「数値を選ぶのが難しかったり迷ったりした場合は、一番近いと思う数字を入れ、迷った理由を備考欄に書いてください。」にする．
  - 巻き戻してよいか：「録画は何度でも巻き戻して構いません。」（分析者側は「動画は」）
  - 発声の無い区間：「発声の無いところは、評価の代わりに0を入力しても大丈夫です。」annotator は 1〜9 に加えて 0 を発声なしの印として受け付ける．値の範囲の台詞（1〜9）の直後に置き，0 が評価の値ではないことが分かるようにする．
- 1 区間に複数の感情があるときは，現状は「1秒間で複数の感情があると思われるときは、一番長く出ていた感情を基に判別してください。」を使う（区間が 1 秒でなければ「1秒間」を書き換える）．設計で別の扱いに決まっていれば，それに従う．

## 練習とアンケート

- 練習は短い区間（10 秒程度）にする．分析者側は `roles.txt` のとおりお手本動画の最初の部分，発声者側は練習のプレイの録画の最初の部分を使う．
- 試行ごとのアンケートは，ある実験と無い実験がある．設計資料（annotator なら `experiment.json` の試行の `survey`）にあれば各評価の直後に置き，無ければ置かない．設計資料が無ければ置かずに，報告で有無を確かめる．
- 試行ごとのアンケートを annotator の `survey` で開くなら，台詞は「評価を終えると画面にアンケートのボタンが出るので、答えてください」にし，リンクは書かない．
- 事後アンケート（実験全体のアンケート）を annotator の `finalSurvey` で開くなら，`template.txt` の事後アンケートの節のリンクを外し，台詞を「最後の評価で「完了」を押すと、画面にアンケートのボタンが出るので、押して回答してください。」にする．ボタンをすべて押すまで終わりの案内が出ないことを，実験者向けのメモ（行頭スペース）で添える．`finalSurvey` を使わないなら `template.txt` のリンクの形のままにする．

## 評価についてのインタビュー

- 評価の理由を試行ごとに聞く実験では，各評価の直後（試行ごとのアンケートの後）に置く．台詞は「快度・覚醒度の評価について、質問をさせていただきます。」とし，質問の中身は台本に書かない．
- 評価の理由を後で聞くなら，評価方法の台詞に「評価の理由は後でお聞きするので、必要に応じて備考欄をメモに活用してください。」を足す（備考欄がある道具のとき）．

## 評価区間

- 評価する範囲を設計で決めているなら，評価方法の台詞にその範囲を書く．例（プレイの始めから声が途切れるまでを評価する設計）：「評価するのは、プレイの始めから「あ」の声が途切れるまでです。制限時間が終わった後も声が続いていたら、そこまで評価してください。」
- annotator で実験者が評価区間を合わせるなら，本番の評価の節の動作のメモにも同じ範囲を書く（例：「制限時間やゴールの後も声が続いていれば、途切れた時点まで含める」）．
