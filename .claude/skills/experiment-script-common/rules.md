# 実験説明（台本）の共通ルール

発声者側（`experiment-script-speaker`）と分析者側（`experiment-script-analyst`）の skill が共通で従うルールである．

実験説明は，実験者が参加者の前で手元に開き，`>` の行を読み上げ，`[* ]` の行のとおりに動くための台本である．参加者に配る説明書ではない．研究室の Scrapbox に貼るので，Scrapbox 記法のまま書く．

## 土台

- 両方の役割で同じ文面の部分（同意・説明，実験の流れ，同意書，謝礼，あアラウド法の説明，事後アンケート・インタビュー・終了，書類）は，同じフォルダの `template.txt` を使う．
- 参加者が快度・覚醒度を評価する部分（分析者側の評価と，発声者側の回顧評価）は，同じフォルダの `evaluation.md` に沿って書く．
- 役割ごとの部分は，同じフォルダの `full-template.txt`（実験説明テンプレートの全文）の該当する部（`[(* 発声者側]` か `[(* 分析者側]`）を土台にする．
- `template.txt` と `full-template.txt` は書き換えない．

## 記法

テンプレートの記法をそのまま使う．Markdown（`#`，`**`，`-`，表）に変えない．

| 書き方 | 意味 |
|---|---|
| `[(* 発声者側]` | 役割の見出し（ページの最上位） |
| `[** 2. 実験タスクの説明]` | 章 |
| `[* 2.1 あアラウド法の説明]` | 節 |
| `> 〜〜` | 実験者が読み上げる台詞 |
| `[* 見本動画を見せる]`（行頭か `>` の中） | 実験者の動作・強調したい台詞 |
| 行頭の半角スペース 1 つ | 実験者向けのメモ（読み上げない） |
| `[[◯◯◯]]` | まだ決まっていない値（ゲーム名，金額，期日など） |
| `[! 要検討]` | 節の中身が未確定であることの印 |
| `[hr.icon]` | 区切り線 |
| `[リンク名 https://…]` | リンク |

台本の中の句読点は，台詞もメモも見出しも「、」「。」にする．日本語の文章を「，」「．」で書く普段の規則より，この規則を優先する（研究室の Scrapbox の表記に合わせるため）．台詞はです・ます調で書く．

## 聞き取り（両方の役割で共通の項目）

依頼に無い項目だけを聞く．役割ごとの skill が「必ず聞く」とする項目が無ければ，書く前に聞く．それ以外は聞かずに `[[◯◯◯]]` で残し，報告で一覧にする．値を推測で埋めない．

| 項目 | 扱い |
|---|---|
| コンテンツ（ゲーム名など）と 1 回の長さ | 必ず聞く |
| 謝礼の額と提出の期日 | 聞かずに `[[◯◯円]]`・`[[◯◯まで]]` |
| 事後アンケートとインタビューの有無 | 聞かずに `template.txt` の形を置き，報告で確かめる |
| 見本動画・アンケート・書類のリンク | 下の「リンク」に従う |

ユーザの作業フォルダに実験の設計資料（研究の正本や計画書，annotator の `experiment.json` など）があれば読み，条件名・順序・試行の数をそれに合わせる．依頼と資料が食い違えば（実験の番号，ゲーム，条件など），書く前にユーザに聞く．

## リンク

テンプレートのリンクは `[[見本動画のリンク]]`・`[[アンケートのリンク]]`・`[[書類のリンク]]` の置き場所にしてある．このリポジトリは公開されているので，実際のリンクは git に入れない．

- 同じフォルダに `links.local.txt`（`名前: URL` の行．git の対象外）があれば，置き場所を `[名前 URL]` の形のリンクに置き換える．
- 無ければ置き場所のまま残し，報告で一覧にする．
- この skill のファイル（`template.txt`，`full-template.txt` を含む）に実際のリンクや研究室のメンバーの名前を書かない．

## 書き方

- `template.txt` と `full-template.txt` の節で今回も使うものは文面を残し，変わる所（ゲーム名，回数，条件）だけを書き換える．
- 「1.3 実験の流れ」の箇条は定型として残さず，今回の手順に合わせて書き換える（回顧評価，条件ごとの評価とアンケート，基準音声の収録など，今回ある手順を入れる）．
- `[! 要検討]` の節は，今回の内容で書き直したら印を外し，手を付けなければ印を残す．
- 本番で同じ手順を繰り返す（同じ条件で 3 回など）なら，1 回分の手順を書き，最後に `[* ここまでを◯回繰り返す]` と書く．同じ節を回数分写さない．

## 保存と報告

- 保存先はユーザの指定に従う．指定が無ければ，作業中の実験のフォルダなど分かりやすい場所に置き，報告でパスを伝える．
- 報告には，残した `[[◯◯◯]]` の一覧，資料に合わせて決めた所，テンプレートから変えた節を書く．台本のページの中には書かない．

## 点検

- ページが Scrapbox 記法だけでできている（`#` の見出し，`-` の箇条書き，Markdown の表が無い）．
- 読み上げる文はすべて `>` で始まり，です・ます調である．実験者の動作は `[* ]`，メモは行頭スペースである．句読点は「、」「。」である．
- 台本の外の前置き（「テンプレートから何を変えたか」など）をページに書いていない．
- 決まっていない値はすべて `[[◯◯◯]]` で，推測の値が入っていない．
- 条件・試行の数・順序の説明が，依頼と設計資料に一致している．
