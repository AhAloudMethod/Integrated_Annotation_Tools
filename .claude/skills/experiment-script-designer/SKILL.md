# 設計者側の実験説明（台本）を書く

まず，`experiment-script-common/rules.md`（共通ルール）を読み，それに従う．`experiment-script-common` は，この skill のフォルダの中にあればそれを，無ければ同じ階層にあるものを使う（以下の `experiment-script-common/` も同じ）．共通の文面は同じフォルダの `template.txt`，設計者側の部分は `roles.txt` の `[(* 設計者側]` の部を土台にする．

## 聞き取り（設計者側で必ず聞く項目）

共通ルールの項目に加えて，次を依頼に無ければ書く前に聞く．

| 項目 | 扱い |
|---|---|
| 設計するもの（ゲーム名，ステージの数など） | 必ず聞く |
| 修正の回数と，条件（プレイヤーの発声あり／なしなど）の分け方（同じ日か，日を分けるか） | 必ず聞く |
| 休憩の長さ | 聞かずに `[[◯◯]]` 分 |
| 設計の注意点の資料のリンク | 聞かずに `[[設計の資料のリンク]]` |
| 思考発話の録音・録画の道具 | 聞かずに `roles.txt` のメモのまま残し，報告で確かめる |

## 構成

1. 実験手順の説明（`template.txt` の同意・概要・流れ・同意書・謝礼・事前アンケート）．概要の `{役割の課題}` は `roles.txt` の文面を今回のゲーム名で埋める
2. 実験タスクの説明：あアラウド法の説明（`template.txt`）→ 設計者向けのまとめの台詞と目的 → 実験タスクについて → 快度と覚醒度（発声あり条件があるときだけ）→ 質問を聞く → ゲームの練習
3. 本試行：ステージの設計（思考発話の説明を含む）→ 休憩 → プレイ動画を見て修正（条件ごとの台詞と両条件共通の台詞）．休憩と修正を修正の回数だけ繰り返す
4. 事後アンケート・インタビュー・終了・書類（`template.txt`）

## 設計者側の規則

- 設計者は数値で評価しない．快度と覚醒度の説明は `template.txt` の部品を，`roles.txt` の設計者側のメモに従って「5」を「中間」に言い換えて使う．基準音声も「快度5、覚醒度5」ではなく「どちらも中間」と言う．
- 思考発話の説明は最初の設計の前に 1 回置き，修正のたびには「先ほどと同じように」と例文だけを置く．例文は設計のとき（「ここで右に曲がらせたい」など）と修正のとき（「思ったより難しすぎたかも」など）で変える．
- 条件で台詞が変わる所（修正の前の基準音声の説明，何を参考に修正点を決めるか）は，`[* 発声あり条件]`・`[* 発声なし条件]`・`[* 両条件共通]` に分けて並べる．
- 条件を日で分けるなら，共通ルールの「2 日に分ける」の形にする．発声あり条件が初めての日には，あアラウド法の説明と快度・覚醒度の説明を必ず読む（1 日目が発声なし条件の参加者が，説明を聞かないまま発声ありの動画を見ないようにする）．
- ゲームの操作説明は，`experiment-script-common/games.txt` にそのゲームの部があれば練習の前に読む．
