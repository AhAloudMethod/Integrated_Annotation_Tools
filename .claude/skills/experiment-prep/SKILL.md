# 実験前準備の Todo リストを作る

相手は，あアラウド法の実験を初めて，または久しぶりに行う学生である．研究室の Scrapbox「実験前準備のガイドライン」を正本とし，その実験に要る準備だけを Todo リストにする．扱うのは実験を最後までやり切るのに要る準備までで，実験設計の確認，実験中の進め方，音声収録の注意，分析，執筆は扱わない．

場面は 3 つある．

- **作る**：何から手を付ければよいかわからない．条件を聞き，リストを作る（3 章）
- **確かめる**：今のリストや準備の状況を見せて，抜けが無いかを聞く（4 章）
- **文面を作る**：募集文や参加者への連絡の文面だけがほしい（3.4）

## 0. 何をしてほしいかを先に聞く

依頼から場面が明らかでないとき（`/experiment-prep` とだけ打たれたときを含む）は，条件を聞く前に，何をしてほしいかを聞く．Todo リストが要らない人に 10 個の条件を並べると，答える手間が無駄になる．

> 何をお手伝いしましょうか．
> 1. 準備の Todo リストを作る
> 2. 今の準備に抜けが無いかを確かめる
> 3. 募集文や参加者への連絡の文面を作る
> 4. その他（実験管理シートの設定の確認など）

1 の返事では，1 章のガイドラインの依頼だけを同じメッセージに入れる．条件（3.1）は，場面が決まってから，その場面で要るものだけを聞く．文面だけなら，文面に入る条件（人数・時間・対象・期間・謝礼の額）だけを聞く．

## 1. 最新のガイドラインを受け取る

ガイドラインは研究室の誰でも更新できる．この Skill は中身を持たず，毎回最新の本文を使う．Scrapbox のプロジェクトは非公開なので，Claude からは読めない．

会話にまだ本文が無ければ，最初の返事で次を頼む．0 章の質問か 3.1 の条件の質問と同じメッセージにまとめ，往復を増やさない．「変更は無い」と言われたら，写しを使い，古い写しである旨の 2 つの注意は省く．

> 最新の「実験前準備のガイドライン」を使いたいので，次のページを開き，本文を全選択（Ctrl+A）してコピーし，ここに貼ってください．
> https://scrapbox.io/ah-aloud/%E5%AE%9F%E9%A8%93%E5%89%8D%E6%BA%96%E5%82%99%E3%81%AE%E3%82%AC%E3%82%A4%E3%83%89%E3%83%A9%E3%82%A4%E3%83%B3

貼られなかったとき（開けない，あとでよい，と言われたときを含む）だけ，`references/guideline-2026-11-05.md` を使う．そのときは次の 2 つをする．頼むのは 1 回だけにする．

- 返事の冒頭に「2026-11-05 時点の古い写しを使っている．最新はリンク先で確かめてほしい」と 1 行書く
- リストの「説明」の先頭に「最新のガイドラインとリストを見比べる」という項目を置き，詳細にリンク先の URL を書く．アーティファクトだけを見返す人にも伝わるようにするため

## 2. 守ること

- **ガイドラインに無いことを足さない**．手順や金額を推測で書かない．ガイドラインに無いが要りそうな準備は，3.2 の「ガイドラインの外から入れる項目」に限る．それ以外は「ガイドラインには無いが」と断って提案に留める
- **人名・アカウント名・個人の URL を写さない**．ガイドラインの例文には先輩や先生の名前，Slack のアカウント名，先輩が自分の実験で使ったフォームの URL が入っている．リストや文面では「先生」「自分の名前」「〔自分の日程調整フォームの URL〕」のように置き換える．研究室の部屋番号や PC の名前（ハチワレ PC など）はそのまま使ってよい
- **テンプレートへのリンクは残す**．研究室で共有するテンプレート（3.2 の「テンプレートへ誘導する」）のリンクは，個人の URL ではないので項目の詳細に入れる．例文の中に出てくる URL は，テンプレートの名前が付いていても個人のものとして扱う．Google の URL に `ouid=` や `/u/数字/` が付いていたら，持ち主やアカウントの番号なので取り除く
- **毎年変わる値は固定しない**．謝礼の基準になる東京都の最低賃金は，「最新の額を自分で確かめる」という子タスクにする．ガイドラインにある額は「◯年◯月時点の例」として添える
- **決めるのは本人**．抜けを指摘しても，足すかどうかは本人に任せる

## 3. 作る

### 3.1 条件を聞く

項目を絞るために，次の条件を 1 回のメッセージでまとめて聞く．依頼から分かるものは聞かない．全部を並べると初めての人は量に圧倒されるので，条件に合わない項目はリストに入れない．

| 条件 | 変わる項目 |
|---|---|
| 実験の名前（「実験4」など） | リストの名前（3.3 の `LIST_TITLE`） |
| 参加者は研究室の外か内か | 外：謝礼の相談，学科 Slack での募集，報酬手数料支払い書．内：研究室 Slack での募集，お礼はお菓子と相互参加 |
| 参加者のおおよその人数と，実験 1 回の時間 | 謝礼の総額，日程調整，同意書の印刷枚数 |
| 発声（「あ」の声）を収録するか | マイク，参加者用ヘッドホン，録画・録音の確認 |
| ゲームを使うか．ステージやコースを変えるか | テストプレイ，変更が反映されているかの確認 |
| 評価や回答に annotator などのツールを使うか | 使い方の説明の用意，設定ファイル（experiment.json）の確認 |
| 実験をいつごろ始めたいか | 「いつまで」の目安 |

次の 3 つは研究室の決まりなので聞かない．

- **謝礼は必ず後日振込**．現金を用意する項目は入れない．募集文などには「後日振込み」と書く
- **場所は予約が入ってから決める**．場所は聞かず，環境の段に「実験の場所を決めて先生に教室予約を頼む」を置く．いつまでは「実験の 2 日前」で，詳細に「教室は実験日の 2 日前までに先生に連絡する」と部屋の候補（一般の教室，ラーニングラウンジ，1108・1209 など）を 1 文で書く．部屋ごとの予約手順は，聞かれたら答える．募集文などの場所は「明治大学 中野キャンパス（教室は前日にお知らせします）」とする
- **生理指標（生体信号）は基本計測しない**．計測機器の項目は，本人が計測すると言ったときだけ入れる

答えが「まだ決めていない」なら，「◯◯を決める」という項目を，その条件で変わる段の先頭に置く．決まっていない条件の細かい手順は並べない．

### 3.2 項目を選んで段に分ける

段は 4 つで，この順に並べる．ガイドラインの見出しは次のように割り当てる．ガイドラインに新しい見出しが増えていたら，内容から近い段を選ぶ．

| 段 | 何の準備か | ガイドラインで当たる所 |
|---|---|---|
| 説明 | 参加者に何をどう伝えるか | 中断時の謝礼の扱いの事前説明（ほかは下の「ガイドラインの外から入れる項目」が中心） |
| タスク | 参加者がやることと，そのための書類 | プレプレ実験，同意書（作成・人数分の印刷・手書きの署名・中断時の扱いの記載） |
| 募集 | 謝礼を決め，参加者を集め，日程を決め，謝礼を払う | 謝礼金の確認，実験者募集，日程調整，参加者への連絡，報酬手数料支払い書（ガイドラインでは同意書の下にあるが，謝礼の支払いなのでここに置く） |
| 環境 | 場所・機材・ソフトを整える | 教室予約，使用機器，録画機材，ケーブル類，ソフトウェア，周辺環境，実験によって要るもの，モニタの運び方 |

**ガイドラインの外から入れる項目**．実験3 の準備で要ったが，ガイドラインには無い．条件に合えば入れる．

- 説明：実験説明の台本を用意する（あれば experiment-script 系の Skill を案内する），教示の言い回しを研究室のメンバーに確かめる，アンケートを確認する，評価ツールの使い方の説明を用意する（ツールを使うときだけ）
- タスク：実験で使う設定ファイル（annotator なら experiment.json）を確認する（ツールを使うときだけ）
- 環境：実験で使う PC で一通り動作を確かめる

各項目は次のように作る．

- **タイトル**：動詞で終える（「同意書を人数分印刷する」）
- **いつまで**：「募集開始前」「募集の直後」「実験の 2 週間前」「実験の 1 週間前」「実験の 2 日前」「実験の前日」「実験当日」「実験後」のどれかにする．日付は，本人が実験の開始日を日付で答えたときだけ添える（「募集開始前（11/10 ごろ）」）．「12 月上旬」のような答えから日付を推測しない
- **詳細**：なぜ要るかを 1〜2 文で書く．ガイドラインに理由があればそれを使う（プレプレ実験：手順・説明・時間はやらないとわからない．同意書：署名は手書きが要る）．理由が無ければ，一般的な理由を短く書いてよい．ただし手順はガイドラインに無いものを作らない
- **子タスク**：ガイドラインで字下げされた細目のうち，忘れやすいものだけを子タスクにする．子タスクは 1 段だけにする

**量の目安**：全体で項目 20 個前後，子タスク込みで 40 個以内にする．超えそうなら，似た細目を 1 つの子タスクにまとめる（「HDMI ケーブル・モニタと PC の電源・延長ケーブル」を「ケーブル類をそろえる」に）か，細目を子タスクにせず詳細に列挙する．

謝礼は「募集」に置き，同意書の項目の詳細に「中断時の謝礼の扱いも書く」と入れて両方から辿れるようにする．

### テンプレートへ誘導する

初めての人は「同意書を作る」と言われても，どこから始めればよいかわからない．研究室にテンプレートがある項目では，詳細の最後に `テンプレート：[名前](URL)` の形でリンクを入れる．Todo の雛形はこの形を押せるリンクにする．

リンクは貼られたガイドラインから次のように作る．

- Scrapbox のページへのリンク `[ページ名]`：`https://scrapbox.io/ah-aloud/` の後ろに，ページ名を URL エンコード（JavaScript の `encodeURIComponent`）して付ける．空白は `_` に置き換えてからエンコードする
- `[名前 https://…]` の形で名前の付いた外部リンク：その URL をそのまま使う．ただし例文（`>` で始まる引用）の中の URL は使わない

2026-11-05 時点のガイドラインにあったテンプレートと，置く項目は次のとおりである．ガイドラインに新しいテンプレートが増えていたら，同じように関係する項目に入れる．

研究室で共有する書類のテンプレートは Google ドライブにある．次の表のリンクは常に使う．

| テンプレート | 置く項目 | リンク |
|---|---|---|
| 実験同意書 | タスク：同意書を作る | https://docs.google.com/document/d/1ZUsygHgdONYC3aGG1XFKeUFoJwOPlEUt/edit |
| 報酬手数料支払い書 | 募集：報酬手数料支払い書を実験後に送る（研究室外の参加者に謝礼を払うときだけ） | https://docs.google.com/spreadsheets/d/11JuC6pcKcdUN_o4WsaKhrbDhRGM03lyrk7dy5MSDJPc/edit |
| 実験後アンケート（フォルダ） | 説明：アンケートを確認する | https://drive.google.com/drive/folders/1YEvTi6leDOStQ_s9JtoJIglCiDCGsCNc |
| 実験説明テンプレート（Scrapbox） | 説明：実験説明の台本を用意する | https://scrapbox.io/ah-aloud/%E5%AE%9F%E9%A8%93%E8%AA%AC%E6%98%8E%E3%83%86%E3%83%B3%E3%83%97%E3%83%AC%E3%83%BC%E3%83%88 |
| 音声収録における注意事項（Scrapbox） | 環境：発声の収録の機材をそろえる（発声を収録するときだけ） | https://scrapbox.io/ah-aloud/%E9%9F%B3%E5%A3%B0%E5%8F%8E%E9%8C%B2%E3%81%AB%E3%81%8A%E3%81%91%E3%82%8B%E6%B3%A8%E6%84%8F%E4%BA%8B%E9%A0%85 |

リンクの無いものは次のように扱う．

- **実験説明の台本**：テンプレートのリンクに加え，詳細に「annotator の experiment-script-speaker / experiment-script-analyst / experiment-script-designer Skill を使えば，今回の実験に合わせた台本を作れる」と書く
- **募集文と参加者への連絡**：リンクは入れない．詳細に「文面はこの Skill に『募集文を作って』と頼めば作れる」と書き，頼まれたら 3.4 で作る．連絡（日程の確定・前日リマインドなど）は「募集文を作る」の子タスクにまとめず，「参加者に日程確定と前日リマインドを送る」の 1 項目にする
- **日程調整の表と AffectGrid シート**：貼られた本文に URL があればそれを使う．写しを使っているときは「リンクはガイドラインのページにある」と書き，ガイドラインのページへのリンクを入れる

### 3.3 リストを出す

既定はアーティファクトで出す．`assets/todo.html` を読み，ファイル全体をそのまま使う．書き換えるのは `// ===== Claude が埋める部分` の 2 行の間だけである．

- `LIST_TITLE`：「実験4 準備 Todo」のように実験の名前を入れる．保存の鍵になるので，同じ人の別の実験と重ならない名前にする
- `INITIAL`：項目の配列．形は `{tier:"募集", title:"…", due:"…", detail:"…", children:[{title:"…", due:"…"}]}`．`tier` は 4 つの段の名前のどれかにする

出したあと，次の 3 点を短く伝える．

- 自分で思いついたタスクは，各段の下の欄から足せる．「編集」から子タスクも足せる
- 進み具合はこのブラウザに保存される．別の端末やブラウザからは見えず，ブラウザのデータを消すと消える．ときどき下の「書き出す」で Markdown を手元に残すとよい
- 準備が足りているか不安になったら，書き出した Markdown をこの Skill に貼れば確かめられる

アーティファクトを作れない環境のとき，または本人が手元のファイルで管理したいと言ったときは，5 章の Markdown で出す．

### 3.4 Slack の文面

募集文や参加者への連絡の文面を頼まれたら，ガイドラインの例文を土台に，聞き取った条件で埋めて出す．ガイドラインにある文面は，謝礼を先生に相談する文，学科 Slack と研究室 Slack の募集文，リアクションした人への DM，日程の確定，日程確定後の案内，前日のリマインド，フォーム未入力へのリマインド，日程の再調整，キャンセルが出たときの再募集である．分からない値は「〔実施期間〕」のように空欄で残し，最後に埋める所を一覧にする．

## 4. 確かめる

1. 本人のリストを受け取る．アーティファクトから書き出した Markdown でも，Scrapbox のリストでも，文章の説明でもよい
2. 3.1 の条件のうち，リストから読み取れず，答えで結果が変わるものだけを聞く
3. ガイドラインと 3.2 の項目を条件で絞り，リストと照らす．言い回しが違っても同じ準備なら済んでいるとみなす
4. 次の形で返す
   - 抜けている項目：段ごとに，`- [ ] タイトル ｜いつまで：…` と，なぜ要るかを 1 行ずつ．急ぐもの（「いつまで」が近いもの，取り返しがつかないもの）を先に書く
   - 気になる点：項目はあるが，ガイドラインの注意が抜けていそうなもの（同意書はあるが手書きの署名に触れていない，など）
   - 抜けが無ければ，そう言い切る
5. 足すかどうかは本人に任せる．足し方は「各段の欄から足す」と案内する．本人が望めば，本人のリストに抜けを足した Markdown を全体で出す．チェックの状態とメモは元のまま残す．アーティファクトの「読み込む」に貼れば置き換わる

## 5. Markdown の形

アーティファクトの書き出し・読み込みと同じ形である．手元で管理する人に出すときもこの形にする．

```markdown
# 実験4 準備 Todo

## 説明
- [ ] 教示の言い回しを研究室のメンバーに確かめる ｜いつまで：実験の2週間前
  - 詳細：言い回しで参加者の受け取り方が変わるため．
  - メモ：返信待ち

## 募集
- [ ] 謝礼額を先生に相談する ｜いつまで：募集開始前
  - 詳細：研究室外の参加者には謝礼を払うため．
  - [ ] 東京都の最低賃金の最新額を確かめる

## タスク
- [ ] 同意書を作る ｜いつまで：実験の2週間前
  - 詳細：署名は手書きが要るため，人数分印刷する．中断時の謝礼の扱いも書く．テンプレート：[実験同意書](https://docs.google.com/document/d/1ZUsygHgdONYC3aGG1XFKeUFoJwOPlEUt/edit)
```

- `## ` の見出しが段，`- [ ]` が項目，字下げした `- [ ]` が子タスク，`- [x]` が完了である
- 「 ｜いつまで：」（全角の縦棒）の後ろが「いつまで」である
- 字下げした `- 詳細：` と `- メモ：` は，直前の項目の詳細とメモである
