# 分析者側の実験説明（台本）を書く

まず，この skill のフォルダと同じ階層にある `experiment-script-common/rules.md`（共通ルール）を読み，それに従う．共通の文面は同じフォルダの `template.txt`，分析者側の部分は `full-template.txt` の `[(* 分析者側]` の部を土台にする．評価の説明は同じフォルダの `evaluation.md`（評価の説明の書き方）を読み，それに沿って書く．

## 聞き取り（分析者側で必ず聞く項目）

共通ルールの項目に加えて，次を依頼に無ければ書く前に聞く．

| 項目 | 扱い |
|---|---|
| 条件（評価方式・動画の種類など）と，条件ごとの動画の本数 | 必ず聞く |
| 評価の道具（スプレッドシートか annotator か，annotator ならどの方式か） | 必ず聞く |
| 動画に入っているもの（音声・ゲーム画面・表情のどれか） | 必ず聞く |
| 条件ごとのアンケート（NASA-TLX など）の有無 | 必ず聞く |

## 構成

1. 実験手順（`template.txt` の同意・概要・流れ・同意書・謝礼）．概要の `{役割の課題}` は「実験では[[◯◯]]秒程度の動画を[[◯◯]]本視聴して、それぞれ感情分析を行なっていただきます。」と「今回は、[[◯◯◯]]をプレイしている際の動画を視聴して、感情分析をしていただきます。」の形にする．
2. 説明：あアラウド法の説明（`template.txt`）→ 分析者向けのまとめの台詞（`full-template.txt` の 2.1 の後半）→ 今回の目的と条件の一覧 → 評価軸 → 評価方法 → 注意事項 → 質問を聞く
3. 条件ごとに：その条件の道具の説明 → 練習 → 本番 → 条件ごとのアンケート（あれば）
4. 事後アンケート・インタビュー・終了・書類（`template.txt`）

## 分析者側の規則

- 教示は `evaluation.md` の分析者側の列に従う（声と画面から発声者の感情を推定する）．
- 動画に表情が入っていなければ，`full-template.txt` の表情への言及と「ゲーム画面のみの動画」の注意を外す．
- 道具の説明が条件ごとに違うときは，`evaluation.md` の部品 3（道具の説明）を条件ごとの節に移し，説明の章には全条件に共通の部品（評価軸・評価方法・注意事項）だけを置く．
