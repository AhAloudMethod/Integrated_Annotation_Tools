# 実験の設定ファイル（experiment.json）を作る

実験モード（`core/experiment.js`）が読む `experiment.json` を作る．形式の詳細は README の「実験モード」の節にある．作ったら必ず `npm run exp-check` で検査し，誤りが無くなるまで直す．

実験フォルダには設定ファイルが 2 つある．役割を混ぜない．

- `experiment.json`（この skill が書く）：実験名，参加者ごとの試行の順，練習，方式の設定（`options`），アンケートの URL．
- `setup.json`（ユーザが通常の画面の「設定」→「実験用の設定を書き出す」で作る）：実験中の画面の設定（`settings`）と，動画ごとの評価区間（`videos`．1 フレーム単位で合わせた開始秒・終了秒など）．この skill は `setup.json` を書かない．評価区間を数で聞き取って書くこともしない（写し間違いを防ぐため）．

## 手順

1. **聞き取る**．足りない項目だけを聞く．答えが無い項目は「既定」を使い，最後に何を既定にしたかを伝える．ただし「必ず聞く」項目は，依頼に書かれていなければ必ず聞いてから書く．

   | 項目 | 既定 |
   |---|---|
   | 実験フォルダの場所 | 無い（必ず聞く） |
   | 使う方式（下の一覧の id） | 無い（必ず聞く） |
   | 本番の動画 | フォルダの動画のうち練習用以外 |
   | 練習の動画 | 名前に practice・練習を含む動画．無ければ練習を入れない |
   | 参加者の数と ID | 方式の数（P01，P02 … と 2 桁で振る） |
   | 方式の順の組み方 | ラテン方格（下の「カウンターバランス」） |
   | 動画の割り振り | 方式と動画の組も釣り合わせる（直交ラテン方格） |
   | 練習の入れ方 | 各方式の本番の直前に，その方式の練習を 1 回 |
   | アンケート（survey）の URL | 無い（必ず聞く．「無し」も答えとして受ける） |
   | 実験の後に 1 回だけ答えるアンケート（finalSurvey）の URL | 無い（必ず聞く．「無し」も答えとして受ける） |
   | 試行ごとに変える設定 | 書かない（`setup.json` の設定を全試行に使う） |
   | 条件名（実験中に画面の上に出す名前） | 必ず聞く．聞くときに，方式の表示名（下の一覧）から作った案を示す（例：`excel` → 「Excel」，`custom` はプリセット名か設計の要点）．「案のまま」「出さない」も答えとして受ける |

2. **フォルダを確かめる**．`ls` で動画の名前と `setup.json` の有無を確かめ，聞き取った名前と合わせる．動画のパスはフォルダからの相対で書く．
   - `setup.json` があれば読み，`videos` に実験で使う動画がすべてあるかを確かめる．足りない動画は，通常の画面で開いて評価区間を合わせ，`setup.json` を書き出し直すようユーザに頼む．
   - `setup.json` が無ければ，作り方（通常の画面で各動画の評価区間を合わせ，「設定」→「実験用の設定を書き出す」で実験フォルダを選んで書き出し，フォルダに入れる）を伝える．`experiment.json` は先に書いてよいが，`setup.json` を入れるまで検査に警告が残ることも伝える．
3. **書く**．フォルダに `experiment.json` を書く（既にあれば，読んでから直す）．UTF-8，インデント 2 にする．
4. **検査する**．リポジトリの直下で `npm run exp-check -- <フォルダ>` を実行する．
   - 誤り（終了コード 1）は全部直して，もう一度実行する．
   - 警告は，意図した設計でなければ直す．意図どおりなら（たとえば動画の順を全員そろえる設計），そのまま残し，理由をユーザに伝える．
5. **報告する**．参加者ごとの順を表で示す（行が参加者，列が本番の順番．練習は省いてよい）．既定を使った項目と，残した警告とその理由も書く．

## 形式

```json
{
  "name": "exp2",
  "survey": "https://docs.google.com/forms/d/e/XXXX/viewform?usp=pp_url&entry.111={pid}&entry.222={mode}",
  "conditions": { "excel": "条件A" },
  "participants": {
    "P01": [
      { "mode": "excel", "video": "practice.mp4", "practice": true },
      { "mode": "excel", "video": "a.mp4" }
    ]
  }
}
```

- `name`（必須）：実験名．英数字と `-`，`_` にする（書き出しのファイル名に入る）．
- `participants`（必須）：参加者 ID ごとの試行の配列．試行は `mode`（必須），`video`（必須），`practice`，`condition`，`options`，`settings`，`survey`，`range` を持つ．
- 同じ参加者の中で，`mode` と `video` の組を重複させない（自動保存のキーが衝突するので誤りになる）．練習の動画を全方式で共有するのはよい（方式が違えば組が違う）．
- `settings`：ふつうは `setup.json` に任せて書かない．ユーザが「この試行だけ見返しを出さない」のように試行ごとに変えたいときだけ，試行の `settings` に書く（`setup.json` より優先する）．使える項目と既定値は次のとおりである（`core/exp-check.js` の `SETTINGS`）．ほかの項目は誤りになる．

  | 項目 | 既定値 | 値 |
  |---|---|---|
  | `axes` | `"va"` | `va`，`pana`，`thayer` |
  | `rate` | `1` | `0.5`，`0.75`，`1` |
  | `afterWrite` | `"hold"` | `hold`，`restore` |
  | `graphEdit` | `true` | 真偽 |
  | `grid` | `true` | 真偽 |
  | `f0` | `false` | 真偽 |
  | `listen` | `true` | 真偽 |
  | `timeline` | `true` | 真偽（評価グラフ） |
  | `videoSize` | `55` | 25〜80 |
  | `padJoy`，`padSlider`，`padSquare` | `true` | 真偽 |
  | `review`，`videoWindow` | `true` | 真偽（見返し，別ウィンドウのボタンを出すか） |
  | `voice` | `false` | 真偽（音声入力のボタンを出すか） |

  評価区間の変更（区切りの編集など）は，実験モードでは設定に関係なくできない．ただし Excel（専用とカスタム）で `options` の `cuts` を `"self"` にした試行では，参加者が区切りを編集できる．

- `range`：評価区間は `setup.json` の `videos` に任せて書かない．同じ動画を試行によって違う区間で評価するときだけ，試行の `range`（`start`，`end`，`bin`，`label`）に書く（`videos` より優先する）．
- `conditions`・`condition`：実験中にヘッダーの進行（「2 / 4　練習」）の後ろと開始の覆いに出す条件名．全体の `conditions` は方式 id から条件名への対応で，同じ方式の試行に共通の名前を付ける．同じ方式で `options` を変えて別の条件にするとき（カスタムの設計違いなど）は，試行の `condition` に書く（`conditions` より優先する）．どちらも無い試行には何も出さない．参加者に見えるので，条件を推測させたくなければ「条件A」のような中立の名前にする．
- `survey`：完了の後に開くアンケートの URL．`{pid}`，`{trial}`，`{mode}`，`{condition}`，`{video}`，`{practice}`，`{name}` を置き換える．全体の値は本番の試行だけに使う．試行に書けば練習でも使い，`false` ならその試行では出さない．2 つ以上なら配列で書き，要素は URL の文字列か `{ "url": …, "label": … }`（`label` はボタンの文言）．
- `finalSurvey`：最後の試行を終えた後に 1 回だけ開くアンケート（実験全体の感想など）．全体にだけ書く．形は `survey` と同じで，最後の試行のアンケートの後ろにボタンを並べる．置き換えは `{pid}` と `{name}` を使う．
- `options`：方式の設定．方式の既定値に重ねる．主なものを下の一覧に示す．

## 方式の一覧

id は `modes/` のファイル名である．一覧が古い可能性があるときは `node -e "console.log(require('./tools/exp-check').modeList())"` で確かめる．

| id | 方式 | 種類 | 主な options（既定値） |
|---|---|---|---|
| `key` | テンキー | 連続 | ― |
| `emujoy` | EMuJoy（マウス・四角平面） | 連続 | `face`（true），`tail`（true） |
| `feeltrace` | FEELTRACE（マウス・円形） | 連続 | ― |
| `rcea` | RCEA（円形ジョイスティック） | 連続 | `spring`（false．離すと中心へ） |
| `darma` | DARMA（ジョイスティック・四角平面） | 連続 | ― |
| `throttle` | FullThrottle（両手・1 軸ずつ） | 連続 | ― |
| `halolight` | HaloLight（色の円） | 連続 | `gradient`（true） |
| `carma` | CARMA（1 次元スライダー） | 連続・1 軸 | `axis`（`"v"` か `"a"`） |
| `ranktrace` | RankTrace（上下限なし） | 連続・1 軸 | `axis`（`"v"` か `"a"`） |
| `excel` | Excel | 区間ごと | `cuts`（`"fixed"`＝評価区間に従う（既定），`"self"`＝参加者が区切る） |
| `affectgrid` | Affect Grid（9×9） | 区間ごと | `autoNext`（false） |
| `sam` | SAM（9 段階の絵） | 区間ごと | `autoNext`（false） |
| `affectrank` | AffectRank（変化時に 8 方向） | 相対の変化 | ― |
| `change` | 変化ボタン | 変化の時点 | ― |
| `custom` | カスタム（設計軸の組み合わせ） | 組み合わせによる | `rep`，`time`，`values`，`input`，`dims`，`scale`，`face`，`trail`，`color`，`border`，`autoNext`，`cuts`（README の「カスタム方式」．`rep: "excel"` と `cuts: "self"` で参加者が区切る Excel になる） |

- CARMA と RankTrace は 1 軸ずつ評価する．快度と覚醒度の両方を取るなら，`options.axis` を `"v"` と `"a"` にした 2 つの試行にする．このとき同じ動画を 2 回使うと方式と動画の組が重複するので，`custom` の 1 軸（`dims`）を使うか，動画を分ける．どうするかはユーザに確かめる．

## カウンターバランス

- **ラテン方格**（既定）：方式が n 個なら n 人で 1 組になり，どの位置にもどの方式が 1 回ずつ現れる．参加者が n の倍数でなければ，検査は位置ごとの差 1 までを許す．
  - 方式の数が偶数なら，直前・直後の組も釣り合う Williams 方格を勧める．行 0 は `0, 1, n−1, 2, n−2, …`，行 i はその各要素に i を足して n で割った余りにする．
  - 奇数なら，Williams 方格は 2n 行になる（上の n 行と，各行を逆順にした n 行）．
- **方式と動画の組**：動画が方式と同じ数なら，方式の順の方格と直交する方格で動画を割り振る．どの位置にもどの動画も 1 回ずつ現れ，どの方式もどの動画とも 1 回ずつ組む．4×4 の例（数字は添字）：

  | 参加者 | 方式の順 | 動画の順 |
  |---|---|---|
  | P01 | 0 1 2 3 | 0 1 2 3 |
  | P02 | 1 0 3 2 | 2 3 0 1 |
  | P03 | 2 3 0 1 | 3 2 1 0 |
  | P04 | 3 2 1 0 | 1 0 3 2 |

  6×6 には直交ラテン方格が無い．このときは方式の順を Williams 方格にし，動画は 1 つずらしの方格で割り振って，残る偏りを警告として伝える．
- 参加者が 1 組（n 人）より多いときは，同じ方格を繰り返す（P05 は P01 と同じ順）．
- 練習は順序の検査に数えない．各方式の本番の直前に置く．

## 検査の警告の読み方

`npm run exp-check` は次の警告を出す．警告があっても実験は始められる．

- `本番の k 番目に現れる方式（動画）が偏っています`：位置の釣り合いが崩れている．方格を直す．
- `方式「x」と組む動画が偏っています`：方式と動画が交絡している．直交する方格で割り振り直す．
- `参加者によって本番の試行の数（方式・動画の組）が違います`：参加者ごとの試行の写し間違いが多い．
- `本番の前に練習が無い方式があります`：練習の入れ忘れ．練習を使わない実験なら，どの参加者にも練習を入れない（1 人でも練習があると，この警告が出る）．
- `動画ごとの評価区間（setup.json の videos）がありません`：`setup.json` がまだ無い．ユーザに通常の画面から書き出してもらう．
- 誤り `動画「x」の評価区間がありません`：`setup.json` の `videos` にその動画が無い．通常の画面でその動画の評価区間を合わせ，`setup.json` を書き出し直してもらう．
