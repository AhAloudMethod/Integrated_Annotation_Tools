# あアラウド 統合アノテーションツール（v1.0）

感情アノテーションの既存の方式を，1 つのツールの中で再現したものである．`index.html` をブラウザで開けば使える．ビルドは要らない．

- `core/`：全方式に共通の処理（動画の再生，上書き，操作ログ，取り消し，自動保存，書き出し）
- `modes/`：方式ごとの入力 UI（1 方式 1 ファイル）
- `style.css`：見た目
- `sam/`：SAM の原典画像を置くフォルダ（置き方は `sam/README.txt`）
- `tests/`：自動テスト（`npm test`）
- 前の版（v0.2）の `../ah_annotator.html` も残してある．

`file://` で直接開けるように，ES Modules は使っていない．`index.html` が `<script src>` でファイルを順に読み込み，グローバルの `AH` でつなぐ．

### 名前空間

名前空間は 3 つある．

- `AH.*`：公開 API．方式ファイル（`modes/`）とテストは，これだけを使う．例は `AH.S`，`AH.register`，`AH.valueAt`，`AH.penDown`，`AH.setCell`，`AH.addEvent`，`AH.mode` である．一覧は `core/init.js` にある．
- `AH.ui.*`：方式ファイルどうしで共有するヘルパ．例は `h`，`nowRow`，`planeCanvas`，`bindHold`，`secStrip`，`samRows`，`heldRate`，`stick`（ジョイスティック），`sliders`（スライダー）である．一覧は `modes/_shared.js` の末尾にある．
- `AH._.*`：core の内部用で，core のファイル間で値と関数を共有する．方式ファイルからは使わない．
  - 各 core ファイルは，最後に `Object.assign(_, {...})` で他のファイルが使う定義を載せる．
  - 先に読み込んだファイルの定義は，冒頭の `const { ... } = _;` で受け取る．
  - 後で読み込むファイルの定義（`_.refresh()`，`_.autosave()` など）と，再代入する状態（選択中の方式 `_.M`，書き込み中の区間 `_.stroke`）は `_.名前` で参照する．

## 新しい方式の足し方

1. `modes/<id>.js` を作り，即時関数の中で `AH.register({...})` を呼ぶ．ヘルパは `const { h, nowRow, ... } = AH.ui;`，状態は `const { S, pen, video } = AH;` で受け取る．
2. `index.html` の `modes/custom.js` より前に `<script src="modes/<id>.js"></script>` を足す．選択肢は読み込み順に並び，`group` が同じ方式は同じ見出しにまとまる．
3. 見た目が必要なら，`style.css` の「方式別」に足す．
4. `tests/modes.test.js` の方式一覧に `<id>` を足し，その方式の操作を 1 つ書く．`tests/structure.test.js` の並び順の期待値も直す．

`AH.register()` に渡すオブジェクトの主な項目は次のとおりである．

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` / `group` / `label` | ○ | 識別子／選択肢の見出し／表示名．`id` はファイル名，書き出しのファイル名，自動保存のキーに使う |
| `model` | ○ | `'series'`（変化点），`'table'`（区間ごとのセル），`'events'`（相対の変化）のどれか．getter でもよい（カスタム） |
| `init` | ○ | 初期値 `{ v, a }`（t=0 の変化点） |
| `mount({ panel, overlay, under })` | ○ | 入力 UI を作る．panel は右の欄，overlay は動画の上，under は動画の下の欄 |
| `update(t)` | | 毎回の再描画（時刻 t の表示） |
| `resize()` | | キャンバスの解像度合わせ（`g = AH.fitCanvas(c)`） |
| `side` | | 右の欄の幅（`'narrow'`，`'normal'`，`'wide'`） |
| `help` | | 「？」に出す説明（HTML） |
| `options` | | 方式の設定の既定値．`S.meta.options` に入り，書き出しにも残る |
| `integer` / `isInteger()` / `unbounded` | | 整数値の方式か／上下限がないか．グラフと `_bins.csv` の集計が変わる |
| `writeMode()` | 連続方式 | `'hold'`（押している間だけ書き込む），`'armed'`（記録オンの間），`null` のどれか |
| `writeAxes()` / `sample()` | 連続方式 | 書き込む軸（`['v','a']` など）／今の入力値 `{ v, a }` |
| `tick(dt)` / `animate` | | 毎フレームの処理／毎フレーム再描画するか |
| `onKey(e)` / `onKeyUp(e)` / `onBlur()` / `onArm(on)` | | キー（処理したら true を返す），フォーカスが外れたとき，記録オン／オフのとき |

値の書き込みには次の関数を使う．使い方は既存の方式を参照してほしい．

- 変化点：`AH.placePoint`，`AH.pushUndo`，`AH.addLog`
- 押している間の入力：`AH.penDown`，`AH.penMove`，`AH.penUp`
- 区間の値：`AH.setCell`，`AH.setCells`
- 相対の変化：`AH.addEvent`

## テスト

```
npm install        # 初回のみ（playwright-core）
npm test           # 全テストを順に実行する（tests/run-all.js）
npm test -- modes  # 一部だけ（structure modes features layout restore samimg fixes vwin spec controls voice vosk f0 axes pad listen review display frame custom export experiment expcheck）
npm run check      # 全 JS に node --check をかける
```

- ブラウザの既定は `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe` である．環境変数 `AH_BROWSER` で変えられる．
- スクリーンショットと各テストの出力（`*.log`）は `tests/out/` に保存する．保存先は `AH_OUT` で変えられる．
- テスト動画は `tests/fixtures/test.mp4`（12 秒）である．消えたら `npm run fixture` で ffmpeg から作り直す．`npm test` も，無ければ自動で作る．
- `samimg` は，`sam/` に原典画像があることを前提にする．
- Vosk のテスト（vosk）は，本物のモデルと合成音声を偽のマイク入力として使う．モデルは `npm run vosk-model` で `models/*.tar.gz` に作る．合成音声は `npm run voice-fixture` で `tests/fixtures/voice.wav` に作る（Windows の音声合成 Haruka を使う）．どちらかが無ければテストを飛ばす．
- 書き出しのテスト（export）は，変化点・区間の値・変化の入力を直接与えて書き出し，手で計算した期待値と CSV・JSON の中身を照合する．
- 実験フォルダの検査のテスト（expcheck）はブラウザを使わず，`npm run exp-check` を実行して出力と終了コードを確かめる．
- 実験モードのテスト（experiment）は，`tests/out/exp_good/` と `tests/out/exp_bad/` に実験フォルダ（テスト動画の複製と `experiment.json`）を作って読み込む．
- ゲームパッドのテスト（pad）は実機を使わない．`navigator.getGamepads` を偽の機器（`window.__pads`，複数台）に差し替え，軸とボタンの値を書き換えて確かめる．
- 再生しながら操作するテストでは，フレームの間隔によって変化点の時刻やサンプル数が少し揺れる．これは正常である．

## 全方式に共通する仕様

### 再生と書き込み

- **再生制御**：どの方式でも一時停止，巻き戻し，シークができる．1 回の視聴で評価し切ることは想定していない．
  - 再生速度は「設定」で選ぶ．再読み込みすると 1 に戻る．1 以外のときは，再生ボタンの角に「×0.75」のように出す．
  - 方式や再生速度の選択欄にフォーカスが残っていても，矢印・文字・Space は選択を変えず，ツールの操作として扱う．
- **連続方式の書き込み**：再生中，「押している間」または「記録オン（R）の間」だけ書き込み，その区間の前の記録を上書きする．
  - 上書きを終えた後ろの値は，「設定」の「上書きした後ろ」で選ぶ．
    - 「最後の値のまま続ける」（既定）：離した時点の値が，元の記録で次に値が変わる点まで続く．頭から通して付け直すとき向けである．
    - 「上書き前の値に戻す」：上書きした区間の直後から元の記録に戻る．一部だけを直すとき向けである．
  - どちらで書いたかは `_strokes` の `after` に残る．
  - 上書きで消えた軌跡も含め，すべての書き込みを `_strokes.csv` と `_session.json` に残す．
- **記録オフでの操作**：スライダー，レバー，RankTrace は記録オフでも動かせる．対象は CARMA，FullThrottle，RankTrace，カスタムのキーボード／ゲームパッド，スライダーの機器である．記録オンにすると，動かした位置から記録が始まる．記録オフのまま再生やシークで時刻が動くと，記録済みの値に追従する．
- **取り消し・やり直し**：Ctrl+Z で取り消し，Ctrl+Y（または Ctrl+Shift+Z）でやり直す．新しく値を変えると，やり直しの履歴は消える．
  - 評価区間の変更（開始，終了，区間の数と長さ，表記，区切りの操作）も同じ履歴に乗る．
  - 履歴の 1 件には評価区間も添えるので，区間の値と区切りがずれずに戻る．
  - 操作ログに `undo`，`redo` を残す．
- **入力をリセットする**（「設定」の「表示・再生」）：今の動画・方式の評価の値を初期値に戻す．対象は連続の値，区間の値，変化の入力である．
  - 確認のダイアログを出す．Ctrl+Z で戻せる．
  - レバーやスライダーなどの入力の位置も初期値に戻る．
  - 書き込みの生データ（`_strokes`）とメモは記録として残す．
  - 操作ログに `reset` を残す．見返しの間は効かない．

### 聴いてから入力

連続の方式で，Excel のように「聴いて判断してから入れる」手順をとる機能である．「設定」の「1区間ずつ聴いてから入力する」でオンにする（既定はオフ，ブラウザに保存）．

1. 再生すると，評価区間の 1 区間の終わり（2 ms 手前）で自動で止まる．この再生では記録しない．
2. 止まっている間に考える．入力を動かすと画面の値は動くが，書き込まない．マウスのクリックも点を置かない．
3. Enter（またはボタン 0）を押すと，同じ区間を始めから音声つきで再生し直し，その間の入力を記録する．書き込み方は記録オンと同じで，最初の値は区間の始めに入る．マウスを離しても記録は続く．
4. 区間の終わりで記録を終え，そのまま次の区間を聴く．最後の区間なら止まる．

- R で，聴いた区間をもう一度聴く（記録しない）．Space は記録せずに次の区間へ進む．
- 記録中に Space を押すかシークすると，そこで記録を終える．
- この機能がオンの間，ヘッダーの記録ボタンは出ない．
- 書き込みは `_strokes` に `end_reason=listen` で残る．
- 区間方式（Excel など）と相対の方式（AffectRank など）には効かない．

### 見返し

ヘッダーの「見返し」または V キーで，評価し終えた記録を止まらずに再生しながら追う．画面（平面の点，レバー，スライダーなど）は記録済みの値を映す．

- 見返しの間は値を変えない．書き込み，記録オン，区間の値，変化の入力，グラフの編集，音声入力を止め，入力面を薄く表示して操作できなくする．方式のキー入力と，ジョイスティック・スライダーの値も渡さない．
- 聴いてから入力がオンでも，区間の終わりで止まらない．
- 効くのは Space，←→，ボタン 0（再生／停止）だけである．もう一度押すと戻る．
- 操作ログに `review`（on／off）を残す．

### 1 フレーム移動

`,` で 1 フレーム戻り，`.` で 1 フレーム進む．「評価区間」の欄のボタンでも動かせる．評価区間の開始と終了をフレーム単位で合わせるための機能である．再生中なら止めてから動く．

- フレームレートは，再生中に表示されたフレームの時刻（`requestVideoFrameCallback`）から推定する．24，25，29.97，30，60 などのよく使う値に近ければ，その値に揃える．
- 推定できないブラウザ（Firefox 系など）と推定の前は 30 にする．「評価区間」の欄で手で直せ，動画ごとに覚える．欄には今のフレーム番号と，値が仮・推定・手入力のどれかを出す．
- 「今の時間を開始にする」「今の時間を終了にする」は，今表示しているフレームの始まり（フレーム番号÷フレームレート）に揃える．
- 使ったフレームレートは，書き出しの `meta.frame_rate` と操作ログの `fps` に残す．

### 評価区間

ヘッダーの「評価区間」で，動画の時刻とは別に設定する．ボタンには開始と終了を「1.5秒〜12秒」のように出す．

- **開始・終了**：動画の秒で指定する．「今の時間を開始にする」「今の時間を終了にする」「動画の最後まで」でも設定できる．
- **区間の数と 1 区間の長さ（秒）**：開始，終了，区間の長さを変えると区間の数を合わせ直し，区間の数を変えると終了を合わせ直す．
  - 区間の長さを変えても，決めた終了から区間の数を決め直すので，終了は縮まない．
  - 終了が区間の区切りに合わないときは，最後の区間を終了までの短い区間にする．端数は捨てない．ただし半フレーム未満の端数は区切りの誤差とみなし，区間にしない．
  - `_bins.csv` の最後の行の終わりも，決めた終了になる．
- **自分で区切る（不揃いの区間）**：
  - 「今の時間で区切る」で，今表示しているフレームの始まりで区間を割る．1 フレーム移動と組み合わせて位置を合わせる．
  - 「近くの区切りを消す」で，今の時刻に最も近い区切りを消す．
  - 「区切り（秒）」の一覧（カンマ区切り）を直接書き換えてもよい．
  - 「等間隔に戻す」で，開始と終了はそのまま等間隔の区間に戻る．
  - 不揃いの間は，区間の数と長さの欄を変えられない．
  - 区間を割ると，区間方式で入れた値を両方に引き継ぐ．区切りを消すと前の区間の値を残し，前が空なら後ろの値を残す．
  - 区切りの操作も Ctrl+Z で戻せる．連続方式と Excel（カスタムの Excel を含む）では，グラフの右クリックでも区切りを置く・動かす・消すことができる（「グラフでの直接編集」）．
  - Excel（専用の方式とカスタムの Excel）では，方式のパネルの「区切り」で「評価区間に従う」（既定）か「自分で区切る」を選ぶ．「自分で区切る」では，パネルに「今の時間で区切る」「近くの区切りを消す」を出し，実験モードでも参加者が区切りを編集できる（`options` の `cuts: "self"`）．
  - 区切りは `meta.range.edges`（[開始, 区切り…, 終了]）に残り，`_bins.csv` もこの区間で集計する．
  - 操作ログに `range_cut`（add／delete／move／list／uniform）を残す．
- **列の表記**：カウントダウン（終了までの残り）かカウントアップ（評価区間の開始からの経過）を選ぶ．カウントアップは区間の始めの時刻を，カウントダウンは区間の終わりから終了までの残りを表記する．
- **覚え方**：評価区間は動画ごとにブラウザに覚える．
  - ファイル名に加え，ファイルの大きさと長さでも覚える．そのため，動画の名前を変えたり別の場所へ移したりしても復元できる．名前で見つかれば，それを優先する．
  - 参加者 ID や入力方式が違っても，同じ動画を開けば同じ区間になる．操作ログに `range_restore` を残す．
- **区間方式との関係**：区間方式（Excel，Affect Grid，SAM，カスタムの区間ごと）は，この区間ごとに値を 1 つ入力する．連続方式でも，書き出しの `_bins.csv` はこの区間で集計する．
- 区間方式（Affect Grid，SAM，カスタムの区間ごと）では，評価区間の外では入力できない．案内を表示し，操作ログに `input_out_of_range` を残す．動画の末尾で止まっているときは最後の区間に入る．
- 評価グラフでは，評価区間の外を薄く表示する．快度と覚醒度の欄の間には区切り線を引く．

### グラフでの直接編集

「設定」の「グラフをなぞって値を編集する」がオンのとき，評価グラフの快度・覚醒度の欄をなぞると値を描き換えられる．

- 左クリックはグラフの編集とシーク，右クリックは区間の区切りの編集に使う．
- **左クリック**：
  - 連続方式：なぞった時間範囲の値を描き換え，その直後は元の値に戻す．
  - 区間方式：なぞった区間の値を設定する．
  - 下端の目盛りの帯はシークに使う．設定をオフにすると，グラフ全体がシーク用になる（実験で操作をそろえたいとき）．
- **右クリック**（連続方式と Excel）：
  - 区切りの線から離れた所で右クリックすると，そこに最も近いフレームの始まりに区切りを置く．
  - 区切りの線の上（左右 6 px 以内．カーソルが左右の矢印になる）で右ドラッグすると，区切りを動かす．隣の区切りの 1 フレーム手前までしか動かない．
  - 区切りの線の上で，動かさずに離すと消す．
  - 1 回の操作を Ctrl+Z の 1 件として戻せる．
  - 開始と終了は「評価区間」の欄で変える．
  - グラフ上ではブラウザの右クリックメニューを出さない．
  - Excel（カスタムの Excel を含む）でも同じ操作で区切りを編集できる．区間を割ると入れた値を両方に引き継ぎ，表の列も増える．
  - Excel 以外の区間方式（Affect Grid，SAM，カスタムの区間ごと）と変化の方式では，右クリックに何も割り当てない．
- グラフでの編集は，`_strokes.csv` の `source=graph` と，操作ログの `graph_draw` / `graph_cells` に残る．

### 表示と画面の配置

- **画面の配置**：ページはスクロールせず，ウィンドウの高さに収める．並びは，ヘッダー 1 段，動画とツールの 2 列，区間方式の欄，評価グラフの順である．入力面（平面，スライダー，SAM の絵など）の大きさは，空いている高さに合わせて決まる．
  - **別ウィンドウ**（ヘッダーのボタン）：動画だけを別ウィンドウに出す．ノート PC で評価し，動画はモニターに出す使い方を想定している．別ウィンドウをモニターへドラッグし，ダブルクリックで全画面にする．別ウィンドウを選んでいても，キー操作は評価側に届く．閉じるか「動画を戻す」で元に戻る．Chrome，Edge，Firefox 系（Zen など）で動く．操作ログの `video_window` に残る．
  - **グラフ**：評価グラフを開閉する．既定は閉じていて，状態はブラウザに保存する．
  - **設定**：動画の大きさ（25〜80％），再生速度，グラフをなぞって編集するかなどを選ぶ．
  - **？**：操作の説明を出す．方式ごとの説明も含む．
- **グリッド線**（「設定」の「グリッド線を表示する」，既定はオフ，ブラウザに保存）：連続の入力面（四角の平面，円，スライダー，レバー）に，整数の境目 1.5，2.5 … 8.5 の薄い線を引く．
  - 四捨五入で同じ整数になる範囲が 1 マスになり，5 のマスが中心に来る．端の 1 と 9 のマスは半分の幅である．
  - 線があると評価が整数に寄る（量子化される）可能性があるので，条件として切り替えられるようにしてある．
  - 操作ログに `grid_display`，書き出しの `meta.display.grid_lines` に残す．
- **動画の音声の F0**：動画を開くと，その音声（体験者の「あ」）の F0（声の高さ）をブラウザの中で計算する．
  - 計算は YIN で行う．16 kHz・モノラルにし，窓 40 ms，10 ms ごと，70〜1000 Hz で求める．小さすぎる音と，声の高さがはっきりしない区間は声なしとする．
  - 評価グラフの 3 段目に，動画全体の曲線と再生位置を出す．縦軸は対数で，範囲はその動画の F0 の分布から決める．ツールの列の上には，今の F0（Hz）とメーターを出す．
  - F0 を見せるかどうかは評価の条件に関わるので，「設定」の「音声の F0（声の高さ）を表示する」で切り替えられる（既定はオン，ブラウザに保存）．
  - 操作ログに `f0_display` を，書き出しの `meta.f0.shown` にも残す．
- **色の設定**（「設定」の「色」）：4 象限（四隅）と 4 軸方向（上下左右）の色を変えられる．
  - 軸方向は「自動」（両隣の象限の中間）にもできる．グラデーションは，この 8 色の間を補間する．
  - RCEA，HaloLight，FEELTRACE，カスタム（位置の色，画面枠の色）で使う．
  - 設定はブラウザに保存し，操作ログの `colors` と書き出しの `meta.colors` に残る．

### 評価軸

- **軸の順番**：快度，覚醒度の順で統一する．値の範囲は 1〜9 である（上下限のない相対尺度を除く）．
- **評価軸の組**（「設定」の「評価軸のラベル」）：Yik, Russell & Barrett（1999）の Figure 1 にある構造から，次の 3 つを選べる．
  - VA（Russell：快度・覚醒度．既定）
  - PANA（Watson & Tellegen：横がポジティブ〔PA〕，縦がネガティブ〔NA〕）
  - Thayer（横がエネルギー，縦が緊張）
- 値の持ち方（横軸・縦軸それぞれ 1〜9，5 が中立）は変わらない．変わるのは，軸の名前，両端のラベル，方式の説明文，色の欄のラベル，書き出しの列名（`pa`・`na`，`energy`・`tension`），音声入力の語（「ポジティブ7」「負の感情3」「エネルギー6」「緊張4」など）である．色と象限の対応は変えない．
- PANA と Thayer は VA の円環を 45° 回した軸である．そこで `_60hz.csv` と `_bins.csv` には，VA に直した値 `va_valence = 5 + (x−y)/√2`，`va_arousal = 5 + (x+y)/√2` も付ける（x, y は横軸・縦軸の中立 5 からのずれ）．上下限のない方式（RankTrace など）では，`_bins.csv` に VA に直した値を付けない（`_60hz.csv` には付ける）．この値は 1〜9 を少しはみ出すことがある（例：ポジティブ 9・ネガティブ 1 → 快度 10.66）．
- SAM，Affect Grid，FEELTRACE，AffectRank は，絵や感情語が VA を前提にしているので VA のままにする．Excel は，感情ラベルの表を VA のときだけ出す．
- 選んだ軸の組は，操作ログの `axes` と書き出しの `meta.axes` に残る．評価の途中で変えるときは確認を出す．

### セッション

- **練習モード**：動画を開く前でも，各ツールを操作できる．値は画面上で動くだけである．動画を開いた時点で，練習中の入力と記録オンの状態は消え，そこから記録が始まる．
- **方式の切り替え**：評価の途中でも切り替えられる．切り替える前の評価は自動保存され，同じ方式に戻すと続きから再開できる．自動保存は「方式＋参加者ID＋動画名」ごとに分ける．
- **参加者 ID の変更**：動画を開いた後に参加者 ID を変えると，この動画の保存データ（全方式分）を新しい ID へ移す．移し先に保存データがあれば確認を出し，キャンセルすると ID を元に戻す．操作ログに `participant_change` を残す．

### コントローラー（ゲームパッド）

ジョイスティックやスライダーの機器（自作の基板など）を Gamepad API で読む．機器のボタンを押すと，ブラウザが機器を認識する．

#### 機器との約束

ツール側で次のとおり決め打ちにしている．基板側をこれに合わせる．

| 入力 | 内容 | 値 |
|---|---|---|
| 軸 0 | ジョイスティックの横（右が＋） | −1〜1，中心 0．横軸の値 = 5 + 軸0×4 |
| 軸 1 | ジョイスティックの縦（Gamepad API のとおり下が＋．ツールの中で符号を反転し，上を高い値にする） | −1〜1，中心 0．縦軸の値 = 5 − 軸1×4 |
| 軸 2 | スライダー 1（+1 が上で，値が高い） | −1 で 1，+1 で 9 の線形（値 = 5 + 軸2×4） |
| 軸 3 | スライダー 2（同上） | 同上 |
| ボタン 0 | 記録のオン／オフ（押した瞬間に切り替える．記録オン（R）の方式のとき） | |

- スライダーの物理的な向きは「+1＝上（奥）」と定義する．基板は，スライダーを上（奥）に動かしたときに +1 を出力する．
- ジョイスティックの遊びは 0.08 で，その内側は中心とみなす．

#### M5Stack の機器

`firmware/atoms3_pad/atoms3_pad.ino` を書き込むと，上の約束どおりの USB ゲームパッド（名前は `AH Annotator Pad (AtomS3)`）になる．アノテータ側の変更は要らない．構成は AtomS3 Lite，Grove Hub（U006），Unit Joystick2（U024-C），PbHub v1.1（U041），Unit Fader（U123）×2 である．

- **配線**：本体の Grove を Grove Hub につなぐ．Grove Hub の残りの口に，Joystick2 と PbHub（I2C の口）を挿す．Fader の 1 本目を PbHub の CH0 に，2 本目を CH1 に挿す．どれも Grove の線のままでよい．
  - Fader は白が位置の電圧，黄が LED である．PbHub は各チャネルの白（IO0）でアナログ値を読む．LED は使わない．
  - I2C の番地は Joystick2 が 0x63，PbHub が 0x61 である．
  - フェーダーが 1 本なら，スケッチの `FADER_CH` の 2 本目を `-1` にする．
- **書き込み**：Arduino IDE のボードマネージャで `esp32`（Espressif．2.0.11 で確認）を入れる．ボードは「M5Stack-ATOMS3」，Tools の USB Mode は「USB-OTG (TinyUSB)」，USB CDC On Boot は「Enabled」を選んで書き込む．
  - 一度書き込むと USB がゲームパッドになる．次から書き込むときは，本体のリセットボタンを緑の LED が点くまで（約 2 秒）押して離し，書き込みモードにしてから書き込む．
- **ボタンと LED**：
  - 本体の画面ボタンがボタン 0（記録）になる．ボタンは，20 ms 続いた状態だけを送る．チャタリングで記録のオン・オフが繰り返されるのを防ぐためである．
  - スティックの押し込みは，強く倒すと入りやすく，値も揺れる．そのため既定では記録に使わない．スケッチの `STICK_PRESS_RECORDS` を `true` にすると使う．
  - 本体の LED は，緑なら Joystick2 と PbHub の両方，黄なら片方だけが見つかった状態を示す．赤はどちらも見つからない状態である．抜き差しすると 1 秒以内に戻る．
  - シリアルモニタ（115200）に読み値を出す．`fails` は，スティックの読み取りに失敗した回数である．
- **I2C の読み方**：番地を書いた後に一度 STOP を出してから読む．Joystick2 と PbHub は STOP を受けてから送る値を用意するので，STOP を出さないと前回の値が返る．
  - スティックの読み取りが一度失敗しただけなら，前の値を保つ．100 ms 続けて失敗したら外れたとみなし，中立にする．
- **向きの確認**：「設定」の「コントローラー」で軸のバーを見ながら，次を確かめる．
  - スティックを右に倒すと軸 0 が＋，手前に倒すと軸 1 が＋になる．
  - フェーダーを奥に動かすと軸 2・3 が＋になる．
  - 逆なら，スケッチの `INVERT_STICK_X`，`INVERT_STICK_Y`，`INVERT_FADER` を `true` にして書き直す．
  - フェーダーを端まで動かしても ±1 に届かないときは，シリアルモニタの `raw` を見て `FADER_MIN`，`FADER_MAX` を合わせる．
- スライダー 2 は，HID の Rz と Rx の両方に送る．ブラウザが軸をどちらの順に並べても軸 3 になるようにするためである．そのため軸は 6 本見え，軸 4 か軸 5 にも同じ値が出る．

#### 方式ごとの使い方

- **ジョイスティック**：EMuJoy，RCEA，FEELTRACE，DARMA，HaloLight，カスタム（インタフェースが平面か円で，入力がマウスかゲームパッド）で使える．
  - スティックの位置がそのまま値になる．円の方式では，円の外の位置を円周に吸着させる．離す（遊びの中に戻す）と中性の 5・5 になる．画面の点もスティックに合わせて動く．
  - マウスもそのまま使える．スティックが遊びの外にある間はスティックが優先で，遊びの中ならマウス（押している間）が効く．
  - 記録：マウスだけのときは「押している間だけ記録」（hold）である．ジョイスティックが使える間（つながっていて「ジョイスティックを使う」がオン）は「記録オン（R またはボタン 0）の間だけ記録」（armed）になり，ヘッダーに記録ボタンが出る．
  - 記録オフの間もスティックで点は動き，記録オンにするとその位置から記録する．記録オンのまま機器を外すと記録オフになり，押している間の記録に戻る．
  - DARMA は，マウスで押している間はマウスの位置，離すと中性になる．
- **四角平面でスティックを角まで届かせる**（「設定」の「コントローラー」，既定はオン）：スティックの可動域は円なので，斜めに倒し切っても横・縦はそれぞれ約 0.71 にしかならず，四角の平面の角（9・9 など）に届かない．
  - 四角の平面（EMuJoy，DARMA，HaloLight，カスタムの四角）では，倒した量（中心からの距離．1 で頭打ち）が四角の縁までの割合になるよう広げる．方向は変えない．斜めに倒し切ると角に，真横に倒し切ると辺の真ん中に届く．
  - このため斜めの方向では，同じ倒し方でも値が中心から離れる．
  - 円の方式（RCEA，FEELTRACE，カスタムの円）には効かない．
  - 操作ログに `pad_square`，書き出しの `meta.display.pad_square` に残す．
- **スライダー**：FullThrottle（1 本目が横軸，2 本目が縦軸），CARMA（評価している軸の回に 1 本目），カスタム（インタフェースがスライダーで，尺度が絶対・時間が連続のとき．2 軸なら 1 本目が横軸・2 本目が縦軸，1 軸なら 1 本目）で使える．
  - スライダーの位置がそのまま値になる（速度ではなく位置で決める）．
  - スライダーを動かすと（揺れ 0.02 を超えたら），その軸はスライダーのものになり，以後はスライダーの位置を値にする．キー（またはマウスのドラッグ）で動かすとキーが優先になる．またスライダーを動かすとスライダーに戻る．つまり，最後に動かしたものが優先される．
  - 記録オフの間もスライダーを動かせば表示が動き，その位置に留まる（記録はしない）．記録オンにすると，その位置から記録する．
  - シークや記録オフに戻したときは，スライダーを手放して記録済みの値に追従する．次にスライダーを動かすと，またスライダーの位置になる．
  - RankTrace（上下限なし）とカスタムの相対尺度は，スライダーの対象外である（ホイールで操作する）．
  - カスタムでマウスを選んでいても，スライダーの機器が使える間は記録オン（R）の間の記録になり，マウスはドラッグで動かす．
- **AffectRank**：AffectRank とカスタムの 8 方向ボタンでは，変化の方向へスティックを大きく倒す（中心からの距離 0.7 以上）と，いちばん近い方向が 1 回入る．倒したままでは続けて入らない．中央付近（0.3 未満）に戻してから次を入れる．`_ranks.csv` の `source` は gamepad になる（クリックとテンキーは input）．
- **RankTrace**：ジョイスティックの縦（上が＋）で入力できる．上下限がないので，位置ではなく速さで値を動かす．倒した量に応じて値が動き（倒し切ると 1 秒に 2．↑/↓ キーと同じ），離すとその値に留まる．記録は記録オン（R またはボタン 0）の間である．スティックで動かした値の書き込みは `source=gamepad`，ホイールとキーで動かした値は `input` になる．

#### 複数の機器

`navigator.getGamepads()` の全機器を見る．ジョイスティック（軸 0・1）とスライダー（軸 2・3）は別々の機器でもよい．どの機器を使うかは「設定」で選べ，既定は自動である．自動のときは次の規則で選ぶ．

1. 最初は，ジョイスティックに最初の機器（番号の小さいもの）を，スライダーに軸を 4 本以上持つ最初の機器（なければ 3 本以上）を使う．機器が 1 台なら，その機器を両方に使う．
2. 別の機器のスティックを大きく倒す（軸 0 か 1 が 0.5 を超える）と，ジョイスティックをその機器に切り替える．今のジョイスティックを倒している間は切り替えない．
3. 別の機器のスライダーを動かす（軸 2 か 3 が前の値から 0.2 を超えて動く）と，スライダーをその機器に切り替える．
4. ボタン 0 は，ジョイスティックかスライダーに使っている機器のどれで押しても効く．

#### 設定と記録

- 「設定」の「コントローラー」で，「ジョイスティックを使う」「スライダーを使う」（既定はオン．オフならつながっていても無視する）と，使う機器（自動か機器名）を選ぶ．
  - どれもブラウザに保存する．キーは `ahann_pad_joy`・`ahann_pad_slider`（`1`／`0`）と，`ahann_pad_joydev`・`ahann_pad_sliderdev`（機器名．空なら自動）である．
  - つながっている機器の名前（`gamepad.id`），何に使っているか，全部の軸の今の値（バーと数値），ボタンの状態を表示する．表示はパネルを開いている間だけ更新する．
- 機器で入れた値を 1 つでも含む書き込みは，`_strokes` の `source=gamepad` になる（マウスとキーは `input`，グラフは `graph`）．`_session.json` の各書き込みには `pad`（役割ごとの機器名 `{ joy, slider }`）が付く．
- 操作ログには `pad_connect`・`pad_disconnect`（value は機器名），`pad_assign`（使う機器が変わった），`pad_setting`（設定の変更）を残す．セッションの始めにも，つながっている機器を `pad_connect`（detail は `at_start`）で残す．
- 書き出しの `meta.gamepads` に，設定と使った機器名を残す．

### 音声入力

ヘッダーの「音声入力」で，声で値を入れる（マイクの許可が必要）．認識のしかたは「設定」の「音声認識モデル」で選ぶ．聞き取った文の解釈（下の言い方と補正）は，どちらを選んでも同じである．

- **Chrome の認識**：Web Speech API を使う．Chrome と Edge だけで動く．音声は Google などのサーバーに送って認識するので，ネット接続が要る．
- **Vosk**：PC の中で認識する（vosk-browser，`vendor/vosk.js`）．Chrome と Firefox 系（Zen など）で使える．音声は PC の外に出ず，ネット接続も要らない．
  - 「聞き取る語を限定する」をオンにすると，快度，覚醒度，数字，秒，再生，停止だけを聞き取る．聞き間違いが減る見込みで，オフのときと比べられる．
  - モデルの用意：`npm run vosk-model` で公式の日本語モデル（vosk-model-small-ja-0.22，約 50 MB）をダウンロードし，`models/vosk-model-small-ja-0.22.tar.gz` に作り直す．ダウンロード済みの zip があれば `npm run vosk-model -- <zip>` とする．
  - 初回は，「設定」の「音声認識モデル」で「Vosk」を選び，「モデルを選ぶ」で `.tar.gz` を選ぶ．モデルはブラウザ（IndexedDB）に保存されるので，次からは選ばなくてよい．「モデルのリセット」で消せる．読み込みには数十秒かかることがある．
  - Chrome の音声認識がないブラウザ（Firefox 系）では，自動で Vosk になる．
  - 数の聞き直し（語を限定するとき）：Vosk は「十五」「三十八」のような数を [unk]（聞き取れない語）にしやすく，「 秒 快 度 よん」のように時刻の数が落ちる．そこで，「秒」「分」の直前に数が無いときと，「度」の直後が [unk] のときは，その部分の音だけを，数の語に限った 2 つ目の認識器で聞き直して数を補う．操作ログに `voice_refix`（value は補った文，detail は元の文）を残す．同梱の vosk-browser 0.0.8 の文法では語の並びを縛れないため，この方法をとっている．
  - マイクの雑音抑制とエコー除去は切ってある．発話の頭が削られて，最初の数が落ちやすいためである．音量の自動調整は使う．
  - 読み仮名の数（「じゅう ご 秒」「に じゅう よん 秒」）と，数だけの発話（「なな さん」「七 三」）も読む．
- **言い方**：「快度7」「覚醒度3」「快度7 覚醒度3」，または数字 2 つの「7 3」（快度・覚醒度の順）で言う．
  - 漢数字，読み（なな，しち など），全角数字も読む．10 などの 2 桁と範囲外の数は値にしない．
  - 1 軸ずつ評価する方式（CARMA と RankTrace の回，カスタムの 1 軸）では，数字 1 つでも入る．
  - 「再生」「停止」でも操作できる．
- **時刻を言う**：「12秒 快度7」「1分5秒 7 3」「十二秒、覚醒度三」のように，時刻を付けて言える．
  - 「15秒」で区切り，3 秒以内に「快度4」と続けても，その時刻に入る．時刻だけの発話は，履歴に「15秒（続けて値を）」と出る．
  - 言った時刻は，評価区間の「列の表記」と同じ読み方をする．カウントダウンなら残り秒で，12 秒の動画で「3秒」と言えば動画の 8 秒になる．カウントアップなら評価区間の開始からの秒である．
  - 言った時刻が評価区間の外なら，値は入らない．
- **値が入る時刻**：時刻を言わなければ，話し始めた時刻（最初の途中結果が届いた時点の動画時刻）に入る．連続の方式では変化点に，区間の方式ではその区間の値になる（評価区間の外には入らない）．相対の方式（AffectRank，RankTrace）では値を入れない．
- **聞き間違いの補正**：認識の候補を最大 5 つ受け取り，値として読めた最初の候補を使う．
  - 化けやすい語を読み替える辞書を持つ．たとえば「街道」「開度」は快度に，「学生」「拡声」は覚醒度に読み替える．軸の語の直後なら「急」「球」を 9 に，「録」を 6 に読む．辞書は `core/voice.js` の `ALIAS` と `READ` にある．
  - 対応している Chrome では，「快度」「覚醒度」を認識の優先語にする．
  - 「設定」に，聞き取りの履歴（最新 10 件．聞き取った文と解釈）を表示する．
- 操作ログに `voice`（オン／オフ），`voice_heard`（聞き取った文と解釈，時刻），`voice_input`（入った値）を残す．Ctrl+Z で取り消せる．

## 実験モード

参加者内で複数の方式を比べる実験に使う．実験者が「実験フォルダ」を選ぶと，参加者ごとに決めた順で試行（方式×動画）が進む．参加者が選べる要素を減らし，各試行のタスク遂行時間を測る．

### 実験フォルダ

動画と 2 つの設定ファイルを 1 つのフォルダに入れる．`file://` のまま動き，サーバーは要らない（Chrome，Edge，Firefox 系で動く）．

```
exp2/
  experiment.json   試行の順・参加者・アンケート（skill experiment-config で作る）
  setup.json        実験中の設定と，動画ごとの評価区間（通常の画面の「実験用の設定を書き出す」で作る）
  practice.mp4
  a.mp4
  b.mp4
```

2 つのファイルは，内容をいちばんよく決められる場所で作る．評価区間は動画を 1 フレームずつ見ながら合わせるので通常の画面で，試行の順は組み合わせなので skill で作る．評価区間だけを直すときは，`setup.json` を書き出し直せばよい．

### setup.json：実験中の設定と動画ごとの評価区間

1. 通常の画面で，実験に使う動画を 1 本ずつ開き，今までどおり評価区間（開始，終了，区間，自分で区切った区間）を合わせる．評価区間は動画ごとにブラウザに覚えられる．
2. 「設定」の「実験用の設定を書き出す」で実験フォルダを選ぶ．書き出しの画面が開く．
   - **設定**：「設定」の欄と同じ項目を，同じ形の欄（選択とチェック）で選ぶ．初めの値は今の画面の設定である．
   - **実験中に出すボタン**：見返し，別ウィンドウ，音声入力のボタンを出すかを選ぶ．
   - **動画ごとの評価区間**：フォルダの動画を並べ，覚えてある評価区間を出す．合わせていない動画は「未設定」と出る．実験で使う動画なら，通常の画面で合わせてから書き出し直す．
3. 「setup.json を書き出す」でダウンロードし，実験フォルダ（`experiment.json` と同じ場所）に入れる．

```json
{
  "settings": { "axes": "va", "rate": 1, "afterWrite": "hold", "timeline": true, "graphEdit": true, "grid": true, "f0": false, "listen": true,
                "videoSize": 55, "padJoy": true, "padSlider": true, "padSquare": true, "review": true, "videoWindow": true, "voice": false },
  "videos": {
    "a.mp4": { "start": 1.533, "end": 11.2, "bin": 1, "label": "countdown", "duration": 12.012 },
    "b.mp4": { "edges": [0.8, 2.5, 4, 10.05], "label": "countdown", "duration": 10.1 }
  }
}
```

- `settings` の項目と既定値（`setup.json` にも `experiment.json` にも書いていない項目は，この値になる．参加者のブラウザに残った値は使わない）：

| 項目 | 既定値 | 内容 |
|---|---|---|
| `axes` | `"va"` | 評価軸の組（`va`，`pana`，`thayer`） |
| `rate` | `1` | 再生速度（`0.5`，`0.75`，`1`） |
| `afterWrite` | `"hold"` | 上書きした後ろ（`hold`，`restore`） |
| `timeline` | `true` | 評価グラフを出す |
| `graphEdit` | `true` | グラフをなぞって値を編集する（`timeline` が `true` のときだけ効く） |
| `grid` | `true` | グリッド線を表示する |
| `f0` | `false` | 音声の F0 を表示する |
| `listen` | `true` | 1 区間ずつ聴いてから入力する（連続の方式だけに効く） |
| `videoSize` | `55` | 動画の大きさ（25〜80％） |
| `padJoy`・`padSlider`・`padSquare` | `true` | コントローラーの設定 |
| `review`・`videoWindow` | `true` | 見返し・別ウィンドウのボタンを出すか |
| `voice` | `false` | 音声入力のボタンを出すか |

- 項目の一覧は `core/exp-check.js` の `SETTINGS` にあり，書き出しの画面の欄と検査はこの表から作る．項目を足すときはここに 1 行足す．
- 実験モードの既定値は，通常の画面の既定値と違う項目がある（`grid`，`f0`，`listen`，`timeline`）．
- 評価区間の変更（評価区間の欄，グラフの右クリックでの区切りの編集）は，設定に関係なく常にできない．
- 色の設定は固定しない（ブラウザに保存した値を使う）．
- `videos`：動画（フォルダからの相対パス）ごとの評価区間．`start`，`end`，`bin`，`label`（`countdown` か `elapsed`）か，自分で区切った区間 `edges`（[開始, 区切り…, 終了]）を持つ．`duration` は書き出したときの動画の長さで，検査に使う．
- 評価区間は，試行の `range`，`videos`，`experiment.json` の全体の `range` の順に優先する．
- `videos` を使うときは，試行で使うすべての動画に評価区間が要る（無ければ誤り）．`videos` が無ければ，どの動画も全体の `range`（無ければ動画全体を 1 秒ごと）で評価する（警告を出す）．
- 試行を読み込むとき，評価区間の終了が動画の長さを超えていたら（フレームの端数 0.02 秒は許す），その試行を始めずに誤りを出す．黙って切り詰めることはしない．

### experiment.json：試行の順・参加者・アンケート

```json
{
  "name": "exp2",
  "survey": "https://docs.google.com/forms/d/e/XXXX/viewform?entry.111={pid}&entry.222={mode}",
  "participants": {
    "P01": [
      { "mode": "excel",     "video": "practice.mp4", "practice": true },
      { "mode": "excel",     "video": "a.mp4" },
      { "mode": "feeltrace", "video": "practice.mp4", "practice": true },
      { "mode": "feeltrace", "video": "b.mp4", "settings": { "review": false } }
    ],
    "P02": [
      { "mode": "feeltrace", "video": "practice.mp4", "practice": true },
      { "mode": "feeltrace", "video": "a.mp4" },
      { "mode": "excel",     "video": "practice.mp4", "practice": true },
      { "mode": "excel",     "video": "b.mp4" }
    ]
  }
}
```

- `name`：実験名．要約のファイル名と，進行の保存に使う．
- `participants`：参加者 ID ごとの試行の配列．カウンターバランスはここで組む．
  - `mode`：方式の id（`modes/` のファイル名）．`video`：フォルダからの相対パス．
  - `practice`：練習の試行なら `true`．本番と同じ画面で評価し，記録も残す．
  - `options`：方式の設定（`S.meta.options`．EMuJoy の `face`，CARMA の `axis`，カスタムの設計軸など）．方式の既定値に重ねる．
  - `settings`・`range`：この試行だけの設定と評価区間．ほかの値より優先する．
  - 同じ参加者の中で，方式と動画の組を重複させない（自動保存のキーが衝突するため）．
- `survey`：各試行の後に開くアンケートの URL．`{pid}`，`{trial}`（1 始まり），`{mode}`，`{video}`，`{practice}`（練習なら 1），`{name}` を，その試行の値（URL エンコードしたもの）に置き換える．Google フォームの事前入力の URL に使える．
  - 全体の `survey` は本番の試行だけに使う．試行に `survey` を書くとそれを使い（練習でも），`false` ならその試行ではアンケートを出さない．
  - 2 つ以上のアンケートは配列で書く．要素は URL の文字列か `{ "url": …, "label": "SUS に答える" }` で，`label` はボタンの文言になる（無ければ「アンケート 1 を開く」など）．例：`"survey": ["https://…/tlx?p={pid}", { "url": "https://…/sus?p={pid}", "label": "SUS に答える" }]`．
- `finalSurvey`：最後の試行を終えた後に 1 回だけ開くアンケート（実験全体の感想など）．形は `survey` と同じ（文字列か配列）で，最後の試行のアンケートの後ろにボタンを並べる．置き換えは `{pid}` と `{name}` を使う．
- `settings`・`videos`・`range`：`setup.json` と同じ形で書ける．`setup.json` の値より優先する．

### 作り方と検査

- **experiment.json を Claude Code で作る**：このリポジトリで「実験の設定を作って」と頼むと，skill `experiment-config`（`.claude/skills/experiment-config/SKILL.md`）が働く．方式，動画，参加者の数，アンケートの URL などを聞き取り，カウンターバランス（既定はラテン方格）を組んで `experiment.json` を書き，下の検査で誤りが無くなるまで直す．
- **検査する**：`npm run exp-check -- <実験フォルダ>` で，ブラウザでフォルダを開いたときと同じ規則（`core/exp-check.js`）で `experiment.json` と `setup.json` を検査する．参加者ごとの順，動画ごとの評価区間，誤り・警告を出す．誤りがあれば終了コードは 1 になる．
- **警告**は，実験を始められるが確かめたほうがよいことである．ブラウザでフォルダを開いたときも，参加者を選ぶ画面に出す．
  - 本番の試行（練習を除く）の各位置に現れる方式・動画の偏り（参加者の数が割り切れないときの差 1 は許す）
  - 方式と組む動画の偏り（方式と動画の交絡）
  - 参加者による本番の試行の数や，方式・動画の組の違い
  - 本番の前に練習が無い方式（練習を 1 つでも使う実験のとき）
  - 動画ごとの評価区間（`videos`）が無いこと

### 進め方

1. 実験者が「設定」の「実験フォルダを開く」でフォルダを選び，参加者と始める試行を選んで「実験を始める」を押す．終えた試行には「（済）」，途中で抜けた試行には「（途中）」が付き，既定では終えていない最初の試行から始まる．
2. 試行ごとに，全画面の覆いに「開始」が出る．この間はキー，マウス，ゲームパッドのボタン 0 が効かない．「開始」にはフォーカスを置かないので，Space などで誤って始まることはない．
3. 参加者が「開始」を押すと評価できる．操作ログに `task_start` を残す．
4. 参加者がヘッダーの「完了」を押すと確認を出し，書き込みを確定して止め，操作ログに `task_end` を残して，その試行の zip を書き出す．以後この試行の値は変えられない．
5. アンケートがある試行では，完了の後にアンケートごとに「アンケートを開く」を出す．押すとアンケートを別のタブで開き，要約の `survey_opened` に開いた数を残す．すべてを押すまで「次へ」は出ない．最後の試行では `finalSurvey` のボタンも並べ，すべてを押すと終わりの案内を出す．
6. 「次へ」で次の試行に移る．

- 実験中，ヘッダーには再生の操作（−1 秒，再生，＋1 秒），時刻，記録ボタン，進行（「2 / 4　練習」など），「完了」だけを出す．参加者 ID，方式，動画を開く，評価区間，設定，説明，グラフの開閉，書き出しは隠す．見返しと別ウィンドウは既定で出し，音声入力は `settings` で許したときだけ出す．
- 方式のパネル内の設定（顔・軌跡などの切り替え，評価する軸，カスタムの設計）も隠す．値は `options` で決める．
- 見返しを許していない試行では V キーも効かない．評価グラフの右クリックで区切りを編集することもできない．
  - ただし Excel（専用の方式とカスタムの Excel）で区切りを「自分で区切る」（`cuts: "self"`）にした試行では，参加者が区切りを編集できる．方式のパネルに「今の時間で区切る」「近くの区切りを消す」を出し，評価グラフを出していれば右クリックも効く．区切りは `meta.range.edges` に残る．
- **抜け方**：Ctrl+Shift+E で確認を出し，ページを読み込み直して通常の画面に戻る．試行の途中なら，そこまでを `_partial` の zip として書き出してから抜ける（操作ログに `task_abort`，要約の `partial` が 1）．実験で当てた設定はブラウザに保存されるが，抜けるとき（とページを閉じるとき）に実験前の値へ戻す．
- **中断したとき**：再読み込みなどで止まったら，フォルダを選び直す．終えていない最初の試行から始まる．途中だった試行は，自動保存から再開するかを尋ねる．再開すると `task_start` の後なので，覆いを出さずに続きから評価する．止まっていた間の時間はタスク時間に入らない（操作ログの経過時間が続きから数えるため）．要約の `n_restore` に再開の回数が残る．

### 結果の書き出しと，途中終了への備え

- **1 試行 1 つの zip**：完了で `<ID>_t01p_<動画名>_<方式id>.zip` を書き出す（番号は 1 始まり，`p` は練習）．中身は，通常の書き出しのファイル一式（`_60hz.csv`，`_bins.csv`，`_events.csv`，`_session.json` など）と，その時点までの全試行の要約 `<ID>_<name>_trials.csv` である．zip はメモリの中で作ってから 1 つのファイルとして書き出すので，一部のファイルだけが保存されることはない．参加者が途中でやめても，最後の zip にそれまでの要約がそろう．
- **書き出し先**：ブラウザのダウンロード先のフォルダに入る．ブラウザはページから任意のフォルダへ書き込めない（Firefox には書き込みの API が無い）．実験用の PC では，ブラウザのダウンロード先を実験フォルダの中（`results/` など）に変えておくとよい．
- **ブラウザにも残す**：zip はブラウザ（IndexedDB）にも残る．参加者を選ぶ画面の「ブラウザに残っている結果」で，1 つずつ，またはまとめて書き出し直せる．ダウンロードに失敗したときや，ファイルを消してしまったときに使う．
- **容量**：zip を残したら，その試行の自動保存（localStorage）は消す．書き出したファイルを確かめたら，「この参加者の記録をブラウザから消す」で zip，進行，途中の自動保存を消せる．

### 記録

- `_session.json` の `meta.experiment` に，実験名，参加者，試行の番号（`trial`，0 始まり），試行の数，練習か，当てた設定（`settings`），方式の設定（`options`），開始・完了の時刻（`start_iso`，`end_iso`），途中で抜けたか（`partial`），要約（`task`）を残す．当てた評価区間は `meta.range` と，操作ログの `exp_trial` の detail に残る．
- 要約（`meta.experiment.task` と `_trials.csv` の 1 行）の列は次のとおりである．時間は，最後の `task_start` から `task_end`（途中で抜けたときは `task_abort`）までの操作ログの経過時間（`wall_ms`）で数える．

| 列 | 内容 |
|---|---|
| `trial` | 試行の番号（1 始まり．ファイル名の `t01` と同じ） |
| `practice` | 練習なら 1 |
| `mode`・`video` | 方式 id と動画 |
| `start_iso`・`end_iso` | 「開始」と「完了」を押した時刻（ISO 8601） |
| `task_ms` | タスク遂行時間（ミリ秒） |
| `play_ms` | そのうち再生していた時間（`play` から `pause`・`ended` まで） |
| `review_ms` | そのうち見返しをしていた時間 |
| `n_play`・`n_seek`・`n_undo`・`n_redo` | 再生，シーク，取り消し，やり直しの回数 |
| `n_strokes`・`n_events` | 連続方式の書き込みの数と，相対の変化の入力の数 |
| `bins`・`filled_v`・`filled_a` | 評価区間の区間の数と，区間方式で値を入れた区間の数（未入力の区間を見つけるため） |
| `n_restore` | 自動保存から再開した回数 |
| `partial` | 途中で抜けた試行なら 1 |
| `survey_opened` | 開いたアンケートの数 |

- 進行（終えた試行とその要約）は，localStorage のキー `ahann_exp:<name>:<ID>` に残す．最後の画面の「要約をもう一度書き出す」で，`_trials.csv` だけを書き出し直せる．

### 書き出し形式（CSV の列）

- ファイル名は `<参加者ID>_<動画名（拡張子なし）>_<方式id><接尾辞>` である．参加者 ID が空なら `noid` にする．実験モードでは参加者 ID の後に試行の番号（`_t01`，練習は `_t01p`）が入り，1 試行分を 1 つの zip にまとめる．
- 文字コードは UTF-8（BOM つき），改行は LF である．`"`，`,`，改行を含む値は `"` で囲み，中の `"` は `""` にする．
- 軸の値は 1〜9 である（上下限のない方式は任意の実数）．未入力は空欄にする．
- 「区間」は評価区間の区間を指す．どのファイルも，`bin`（0 始まりの番号），`label`（列の表記．カウントダウンかカウントアップ），`t_start`，`t_end`（動画の秒，小数 3 桁）で始まる．

| ファイル | 列 | 内容 |
|---|---|---|
| `_60hz.csv` | `frame, t, valence, arousal` | frame は 0〜floor(動画の長さ×60)，t は frame/60（小数 4 桁）．値は直前の変化点の値（階段状） |
| `_bins.csv`（整数値の連続方式：テンキー，カスタムの 9 段階×連続） | `bin, label, t_start, t_end, valence, arousal` | 区間内の 60 Hz の値のうち，最も長く続いた値（同数なら先に現れた値） |
| `_bins.csv`（連続値・上下限あり） | `…, valence_mean, arousal_mean, valence_r9, arousal_r9` | 区間内の 60 Hz の値の平均（小数 3 桁）と，それを四捨五入した 9 段階 |
| `_bins.csv`（連続値・上下限なし：RankTrace，カスタムの相対尺度） | `…, valence_mean, arousal_mean` | 区間内の平均 |
| `_bins.csv`（区間方式：Excel，Affect Grid，SAM，カスタムの区間ごと） | `…, valence, arousal` | 入力値（未入力は空欄） |
| `_bins.csv`（AffectRank，変化ボタン） | `…, n_changes, sum_d_valence, sum_d_arousal` | 区間内の変化の回数と，方向（−1/0/+1）の合計 |
| `_changepoints.csv` | `axis, t, value, initial` | axis は valence か arousal．initial が 1 の点は t=0 の初期値 |
| `_strokes.csv`（書き込みが 1 回以上あるとき） | `stroke, source, axes, t, valence, arousal` | stroke は書き込みの番号．source は input（マウスとキー），gamepad（ジョイスティックかスライダーの機器の値を含む），graph（グラフでの編集）のどれか．axes は v，a，va のどれか．書き込んでいない軸は空欄 |
| `_ranks.csv` | `t, label, d_valence, d_arousal, source` | 変化の入力の時刻，方向の名前，方向（−1/0/+1），入れ方（input はクリックとキー，gamepad はジョイスティック） |
| `_events.csv` | `wall_ms, video_t, type, axis, value, detail` | wall_ms はセッション開始からの経過ミリ秒（復元したときは続きから），video_t はそのときの動画の秒 |

`_events.csv` の `type` は次のとおりである．

| 分類 | type |
|---|---|
| セッション | `session_start`，`restore`，`mode_switch`，`export` |
| 実験モード | `exp_trial`（試行を読み込んだ．value は試行の番号，detail は実験名・方式・動画・練習か），`task_start`（開始），`task_end`（完了），`task_abort`（試行の途中で実験モードを抜けた） |
| 再生 | `play`，`pause`，`seek`（detail は移動前の時刻），`ended`，`rate`，`fps`（フレームレートの推定・手入力） |
| 評価区間 | `range`，`range_cut`（区切りを置いた・動かした・消した） |
| 入力 | `input`／`input_same`（テンキーなど），`click`（一時停止中のクリック），`delete`，`stroke`（detail は区間，サンプル数，終わった理由），`arm`／`disarm` |
| 区間の値 | `cell_input`／`cell_clear`／`cell_grid`／`cell_sam`／`cell_custom`，`cell_focus`，`memo` |
| 相対の変化 | `rank`（AffectRank） |
| グラフ | `graph_edit`，`graph_draw`／`graph_cells` |
| 取り消し | `undo`，`redo`（やり直し），`reset`（入力をリセットした） |
| 設定 | `option`，`grid_display`（グリッド線），`pad_square`（スティックを四角に広げる） |
| 聴いてから入力と見返し | `listen_mode`（設定），`listen_pause`（区間の終わりで止まった．detail は区間），`listen_record`／`listen_record_end`（区間を再生し直して記録した始めと終わり），`listen_replay`（R でもう一度聴いた），`review`（見返しの on／off） |
| コントローラー | `pad_connect`／`pad_disconnect`（value は機器名，detail は番号と軸・ボタンの数），`pad_assign`（ジョイスティックかスライダーに使う機器が変わった），`pad_setting`（コントローラーの設定） |

`_session.json` は `{ meta, data, log }` である．

- `meta`：参加者 ID，動画名，長さ，開始時刻，ツールの版（`ah-annotator-v0.5`），方式，方式の設定，評価区間，色の設定（`colors`），聴いてから入力で評価したか（`listen`：`on`），ゲームパッド（`gamepads`）を持つ．実験モードでは `experiment` も持つ（「実験モード」の節）．
  - `gamepads` の中身は，`use`（使うか），`device`（選んだ機器か auto），`joystick`・`slider`（書き出した時点で使っている機器名），`connected`（つながっている機器），`used`（書き込みに使った機器 `{ role: joy|slider, id }`）である．
- `data`：変化点（`points`），書き込み（`strokes`．機器で入れたものは `source: 'gamepad'` と `pad` を持つ），区間の値（`cells`），相対の変化（`events`），メモを持つ．
- `log`：`_events.csv` と同じ内容である．

自動保存は，localStorage のキー `ahann4:<方式id>:<参加者ID>:<動画名>` に `{ meta, data, log, undo（直近 10 回分） }` を入れる．「動画の大きさ」の設定は `ahann_vidsize` に入れる．

## 原典の仕様と改変点の対応表（付録の下書き）

| 方式 | 原典 | 再現した仕様 | 改変点・PC への置き換え | 要確認 |
|---|---|---|---|---|
| Excel | 現行の評価シート（CHI 実験 2 版） | 区間ごとのセル（既定は 1 秒），1〜9 の値，ラベル・プロット表，メモ欄 | 操作ログを取るため HTML で再現した．行は快度→覚醒度の順に変えた．入力値の検査と，再生中の列の強調を足した | 現行シートは 29 列で 0:00 の列がない．評価区間の開始と区間の数で合わせられる |
| Affect Grid | Russell et al. (1989) | 9×9 のマス，外周の 8 ラベル | 原典は刺激全体に 1 回だが，評価区間ごとに使う．直前の区間のマスを薄く表示する．「入力後に次の区間へ」を選べる | ― |
| SAM | Bradley & Lang (1994) | 9 段階（5 体の絵と，その間の 4 つの小円） | 支配性の軸を削った．原典は刺激全体に 1 回だが，評価区間ごとに使う．中間の値が押しにくくならないよう，絵のボタンと小円のボタンを同じ大きさにした．快度は左が不快になるよう，原典と左右を反転した．`sam/` に原典画像を置けばそれを使い，なければ自作の簡略版を使う | 原典画像の入手 |

| RCEA | Zhang et al. (2020) | 円形の仮想ジョイスティック，Itten の四象限色，画面枠の色によるフィードバック | モバイル向けの設計を PC とマウスに置き換えた．円の外に軸のラベル（快，不快，覚醒，眠気）を付けた．ジョイスティックは動画に重ねず，ツールの列に置く（画面枠の色は動画の枠に付ける）．操作方式は「位置がそのまま値」が既定で，「離すと中心へ」も選べる | どちらの操作方式を採るか |
| DARMA | Girard & Wright (2018) | 物理ジョイスティックの位置がそのまま値（離すと中性に戻る），2 次元 | ブラウザの Gamepad API でつなぐ（軸 0・1．機器との約束は「コントローラー」の節）．記録オン（R キーかボタン 0）の間だけ記録する．機器がなければマウスで代用する | 使うスティック（市販品か自作か） |
| FullThrottle | Fayn et al. (2022) の操作方式 | 両手で 1 軸ずつ独立に操作し，レバーは離した位置に留まる | 構成概念を PANA（単極）から VA（快度・覚醒度）に置き換え，操作方式だけを借りた．キーボード（W/S，↑/↓．押している間レバーが動く）かスライダーの機器（軸 2・3．位置がそのまま値）で操作する | 物理スロットルを使うかどうか |
| HaloLight | Xue et al. (2021)，Woodworth & Borst (2024) | 四象限の色（赤がストレス，青が悲しみ，緑がリラックス，黄が興奮），不透明度が強度（円全体をその色で塗る）．Gradient 版（隣の色を混ぜる）も選べる | VR を PC に置き換えた．動画の下部に円を出し，右の入力面をマウスで操作する（ジョイスティックでも可．位置がそのまま値） | 原典（Xue et al.）が手元にない．VR での入力方法 |
| CARMA | Girard (2014) | 1 次元のスライダー，マウスかキーボードで操作，1 秒平均を出力 | VA を 1 軸ずつ 2 回に分けて評価する．記録オン（R）の間だけ記録する | 原典の既定の尺度（−4〜+4 など） |
| RankTrace | Lopes et al. (2017) | 1 次元・上下限なし，ホイール入力，過去の軌跡全体を表示，数値は非表示 | 原典は緊張感の 1 次元だが，快度・覚醒度を 1 軸ずつ 2 回に分けて評価する．↑/↓ キーと，ジョイスティックの上下（倒した量が速さ）でも入力できる | 1 回のホイール操作あたりの変化量 |
| AffectRank | Yannakakis & Martinez (2015) | 変化を感じたときだけ 8 方向から選ぶ（時間も値も離散），選んだ方向が緑に光る | テンキーの配置（8 が覚醒，9 が覚醒・快 …）と，ジョイスティックを倒した方向でも入力できるようにした | ― |
| テンキー | 本研究の試作 | 数字キーで変化点を置く | ― | ― |
| 変化ボタン | 本研究の試作 | 感情が変わったと感じた瞬間にボタン（または Enter）を押すだけで，値も方向も入れない | 評価の粒度（区間の長さ）を決める手がかりにする | ― |

## カスタム方式（設計軸の組み合わせ）

入力方式「カスタム」では，次の設計軸（設定欄の「設計」）を自由に組み合わせられる．先行研究にない組み合わせ（SAM の絵×時間連続，四角平面×区間ごと，グリッド×1 軸ずつなど）も作れる．設定欄の下には，今の組み合わせがどのプリセットに当たるかを出す．どれにも当たらなければ「プリセットに該当しない組み合わせ」と出す．

| 設計軸 | 選択肢 |
|---|---|
| インタフェース | 四角平面／円／9×9 グリッド／SAM の絵／1〜9 ボタン／Excel（セル）／スライダー 2 本／8 方向ボタン（変化の方向） |
| 時間 | 連続（時刻に書き込む）／区間ごと（評価区間に従う）．8 方向ボタンでは選ばない（変化の時点で入れる）．Excel は区間ごとだけ |
| 値 | 連続値（1〜9 の小数）／9 段階（1〜9 の整数）．平面，円，スライダーで選ぶ．グリッド，SAM，ボタン，Excel，8 方向ボタンは 9 段階だけ，相対尺度は連続値だけ |
| 入力 | マウス／キーボード／ゲームパッド．9 段階のインタフェースと区間ごとでは，マウスとキーボード（数字）だけ．8 方向ボタンはマウスとテンキー．Excel はキーボード（セルに入れる）だけ |
| 次元 | 2 軸同時／快度のみ／覚醒度のみ（1 軸ずつ評価する回）．1 軸のとき，もう片方の軸は 5 に固定し，記録しない（画面の点も 5 の線上だけを動く）．8 方向ボタンでは，その軸だけが変わる 2 方向になる |
| 尺度 | 絶対（1〜9）／相対（上下限なし．スライダー×連続のときだけ） |
| フィードバック | 顔／軌跡／位置の色／画面枠の色．Excel と 8 方向ボタンには無い |
| 区切り | 評価区間に従う／自分で区切る．Excel だけで選ぶ（下記） |

書き込み方は組み合わせで決まる．

- 9 段階のインタフェース（グリッド，SAM，ボタン）×連続：クリックか数字キーで，その時刻に変化点を置く．
- 平面・円・スライダー×連続×マウス：押している間だけ書き込む．値が 9 段階なら，書き込む値を整数に揃える．
- 平面・円・スライダー×連続×キーボード／ゲームパッド：記録オン（R）の間だけ書き込む．ゲームパッドは，平面と円ならジョイスティック（位置が値．離すと中性），スライダーならスライダーの機器（位置が値）を使う．
- 相対尺度でマウスを選んだときは，ホイールで操作する．
- 平面・円・スライダー×連続×マウスでも，ジョイスティック（平面・円）かスライダーの機器（スライダー・絶対）が使える間は，記録オン（R）の間だけ書き込む（「コントローラー」の節）．
- 区間ごと：どのインタフェースでも，今の区間の値を設定する．値が連続値なら小数，9 段階なら整数になる．
- Excel：Excel 方式と同じ表（行が軸，列が評価区間）のセルに 1〜9 を入れる．1 軸なら，その軸の行だけを出す．ラベル・プロット表とメモ欄も出す．評価グラフの右クリックで区切りを編集できる（実験モードを除く）．
  - 区切りを「自分で区切る」にすると，方式のパネルに「今の時間で区切る」「近くの区切りを消す」を出す．実験モードでも参加者が区切りを編集できる（右クリックも効く）．参加者に評価の粒度を決めさせる条件に使う．プリセットの判定には区切りの選び方を使わない．
- 8 方向ボタン：変化を感じたときだけ方向を選ぶ．AffectRank と同じ相対イベントモデルで，書き出しは `_ranks.csv` になる．
- 軌跡（フィードバック）は，実際に評価した範囲だけを描く．書き込み中はその書き始めから，再生だけのときは最初に記録した時刻から描く．書き始める前の値（初期値の 5・5 など）からは線を引かない．

プリセット（EMuJoy，FEELTRACE，RCEA，DARMA，FullThrottle，CARMA，RankTrace，テンキー，Excel，Affect Grid，SAM，AffectRank に当たる組み合わせ）を読み込み，そこから 1 軸だけ変えることもできる．専用の方式にあってカスタム方式に入れていないものは，FEELTRACE の感情語，RCEA の動画上のジョイスティック，HaloLight の円，RankTrace の軌跡全体の表示である．
