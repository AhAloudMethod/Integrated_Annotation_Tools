# あアラウド アノテーション 試作（v0.5）

修論実験2の候補ツールを、同じ土台の上で再現したプロトタイプ。`index.html` をブラウザ（Chrome / Edge）で開いて使う。ネットワーク接続は不要。

- `core/`：全方式に共通の部分（動画再生、再生制御、巻き戻したときの上書き、操作ログ、取り消し、自動保存、書き出し）
- `modes/`：各方式の入力UI（1方式1ファイル）
- `style.css`：見た目（共通と方式別）
- `sam/`：SAM の原典画像を置くフォルダ（置き方は `sam/README.txt`）
- `tests/`：自動テスト（`npm test`）
- 前の版の `../ah_annotator.html`（v0.2）は残してある

ビルドは不要。ES Modules（import/export）は使わず、`index.html` が `<script src>` で順に読み込み、グローバルの `AH` でつなぐ（`file://` で直接開けるようにするため）。

### 名前空間

- `AH.*`：公開 API。方式ファイル（`modes/`）とテストはこれだけを使う（`AH.S`、`AH.register`、`AH.valueAt`、`AH.penDown`、`AH.setCell`、`AH.addEvent`、`AH.mode` など。一覧は `core/init.js`）。
- `AH.ui.*`：方式ファイルどうしで共有するヘルパ（`h`、`nowRow`、`planeCanvas`、`bindHold`、`secStrip`、`samRows`、`heldRate`、`stick`（ジョイスティック）、`sliders`（スライダー） など。一覧は `modes/_shared.js` の末尾）。
- `AH._.*`：core の内部用。core のファイル間で共有する値・関数を置く。方式ファイルからは使わない。
  - 各 core ファイルは最後に `Object.assign(_, {...})` で他のファイルが使う定義を載せる。
  - 先に読み込まれたファイルの定義は、冒頭の `const { ... } = _;` で受け取る。
  - 後で読み込まれるファイルの定義（前方参照。例：`_.refresh()`、`_.autosave()`）と、再代入される状態（`_.M`＝選択中の方式、`_.stroke`＝書き込み中の区間）は `_.名前` で参照する。

## 新しい方式の足し方

1. `modes/<id>.js` を作り、即時関数の中で `AH.register({...})` を呼ぶ。必要なヘルパは `const { h, nowRow, ... } = AH.ui;`、状態は `const { S, pen, video } = AH;` で受け取る。
2. `index.html` の `modes/custom.js` より前（選択肢に出したい位置）に `<script src="modes/<id>.js"></script>` を足す。選択肢は読み込み順に並び、`group` が同じものは同じ見出し（optgroup）にまとまる。
3. 必要なら `style.css` の「方式別」に見た目を足す。
4. `tests/modes.test.js` の方式一覧に `<id>` を足し、その方式の操作を1つ書く。`tests/structure.test.js` の並び順の期待値も直す。

`AH.register()` に渡すオブジェクトの主な項目：

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` / `group` / `label` | ○ | 識別子（ファイル名・書き出しのファイル名・自動保存のキーに使う）／選択肢の見出し／表示名 |
| `model` | ○ | `'series'`（変化点）・`'table'`（区間ごとのセル）・`'events'`（相対の変化）。getter でもよい（カスタム） |
| `init` | ○ | 初期値 `{ v, a }`（t=0 の変化点） |
| `mount({ panel, overlay, under })` | ○ | 入力UIを作る。panel＝右の欄、overlay＝動画の上、under＝動画の下の広い欄 |
| `update(t)` | | 毎回の再描画（時刻 t の表示） |
| `resize()` | | キャンバスの解像度合わせ（`g = AH.fitCanvas(c)`） |
| `side` | | 右の欄の幅：`'narrow'`・`'normal'`・`'wide'` |
| `help` | | 画面下の説明（HTML） |
| `options` | | 方式の設定の既定値（`S.meta.options` に入り、書き出しにも残る） |
| `integer` / `isInteger()` / `unbounded` | | 整数値の方式か／上下限なしか（グラフ・`_bins.csv` の集計が変わる） |
| `writeMode()` | 連続方式 | `'hold'`（押している間だけ書き込む）・`'armed'`（記録オン（R）の間）・`null` |
| `writeAxes()` / `sample()` | 連続方式 | 書き込む軸（`['v','a']` など）／今の入力値 `{ v, a }` |
| `tick(dt)` / `animate` | | 毎フレームの処理／毎フレーム再描画するか |
| `onKey(e)` / `onKeyUp(e)` / `onBlur()` / `onArm(on)` | | キー（処理したら true を返す）・フォーカスが外れたとき・記録オン／オフのとき |

値の書き込みは、変化点なら `AH.placePoint` ＋ `AH.pushUndo` ＋ `AH.addLog`、押している間の入力なら `AH.penDown/penMove/penUp`、区間なら `AH.setCell` / `AH.setCells`、相対なら `AH.addEvent` を使う（既存の方式を参照）。

## テスト

```
npm install        # 初回のみ（playwright-core）
npm test           # 全テストを順に実行（tests/run-all.js）
npm test -- modes  # 一部だけ（structure modes features layout restore samimg pip-fallback fixes vwin spec controls voice vosk f0 axes pad）
npm run check      # 全 JS に node --check
```

- ブラウザは既定で `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`。環境変数 `AH_BROWSER` で変えられる。
- スクリーンショットと各テストの出力（`*.log`）は `tests/out/` に保存される（`AH_OUT` で変えられる）。
- Vosk のテスト（vosk）は、本物のモデル（`models/*.tar.gz`、`npm run vosk-model`）と合成音声（`tests/fixtures/voice.wav`、`npm run voice-fixture`。Windows の音声合成 Haruka を使う）を偽のマイク入力として使う。どちらかがなければ飛ばす。
- テスト動画は `tests/fixtures/test.mp4`（12秒）。消えた場合は `npm run fixture` で ffmpeg から作り直す（`npm test` も無ければ自動で作る）。
- `samimg` は `sam/` に原典画像があることが前提。
- ゲームパッドのテスト（pad）は実機を使わず、`navigator.getGamepads` を偽の機器（`window.__pads`。複数台）に差し替え、軸・ボタンの値を書き換えて確かめる。
- 再生しながらの操作は、フレームの間隔で変化点の時刻やサンプル数が少し揺れる（正常）。

## 全方式に共通する仕様

- **再生制御**：全方式で一時停止、巻き戻し、シークができる。1回の視聴で評価し切ることは想定しない。
  - 再生速度は「設定」で選ぶ（再読み込みすると 1 に戻る）。1 以外のときは再生ボタンの角に「×0.75」のように出す。選択欄（方式・再生速度など）にフォーカスが残ったまま矢印・文字・Space を押しても選択は変わらず、ツールの操作（再生・入力）として扱う。
- **連続方式の書き込み**：再生中に「押している間」または「記録オン（R）の間」だけ書き込み、その区間の前の記録を上書きする。書き込みを終えた後の値は「設定」の「書き込みを終えた後」で選ぶ。既定の「その値を保つ」は、離した（記録オフにした）時点の値が、元の記録が次に変わる点まで続く。「元の値に戻す」は、書き込み区間の直後から上書き前の値に戻す（途中だけを書き直すとき向け）。どちらで書いたかは `_strokes` の `after` に残る。上書きで消えた軌跡も含め、すべての書き込みを `_strokes.csv` と `_session.json` に残す。
- **聴いてから入力**（連続の方式。「設定」の「1区間ずつ聴いてから入力する」、既定オフ・ブラウザに保存）：Excel のように「聴いて判断してから入れる」手順を、連続の入力のまま行う。
  1. 再生すると、評価区間の1区間の終わりで自動で止まる（聴く。記録しない。止まる位置は区間の終わりの 2 ms 手前で、今の区間＝聴いた区間）。
  2. 止まっている間に考える。入力（マウス・キー・ジョイスティック・スライダー）を動かすと画面の値は動くが、書き込まない（マウスのクリックも点を置かない）。
  3. Enter（またはボタン0）で、同じ区間を始めから音声つきで再生し直し、その間の入力を記録する（記録オンと同じ連続の書き込み。最初の値は区間の始めに入る。マウスは離しても記録は続く）。
  4. 区間の終わりで記録を終え、そのまま次の区間を聴く（1 に戻る）。最後の区間なら止まる。
  - R で聴いた区間をもう一度聴く（記録しない）。Space は記録せずに次の区間へ。記録中に Space・シークすると、そこで記録を終える。記録オン（R）の記録ボタンは出ない。
  - 書き込みは `_strokes` に `end_reason=listen`（区間の終わりまで記録したとき）で残る。区間方式（Excel など）と相対の方式（AffectRank など）には効かない。
- **取り消し・やり直し**：Ctrl+Z で取り消し、Ctrl+Y（または Ctrl+Shift+Z）でやり直す。新しく値を変えると、やり直しの履歴は消える。操作ログに `undo`・`redo` を残す。
- **区切りの線**（「設定」の「入力面に区切りの線（整数の境目）を表示する」、既定オフ・ブラウザに保存）：連続の入力面（四角の平面・円・スライダー・レバー）に、整数の境目 1.5・2.5 … 8.5 の薄い線を引く。四捨五入で同じ整数になる範囲が1マスになり（端の 1 と 9 のマスは半分の幅）、5 のマスが中心に来る。評価が整数に寄る（量子化される）可能性があるので、条件として切り替えられるようにした。操作ログに `grid_display`、書き出しの `meta.display.grid_lines` に残す。
- **入力をすべて消す**（「設定」の「表示・再生」のボタン）：今の動画・方式の評価の値（連続の値・区間の値・変化の入力）を初期値に戻す。確認のダイアログを出し、Ctrl+Z で戻せる。レバー・スライダーなどの入力の位置も初期値に戻る。書き込みの生データ（`_strokes`）とメモは記録として残す。操作ログに `reset` を残す。見返しの間は効かない。
- **1フレーム移動**（`,`＝戻る、`.`＝進む。「評価区間」の欄のボタンでも可）：評価区間の開始・終了をフレーム単位で合わせる。再生中なら止めてから動く。
  - フレームレートは、再生中に表示されたフレームの時刻（`requestVideoFrameCallback`）から推定する（よく使う値 24・25・29.97・30・60 などに近ければそれに揃える）。推定できないブラウザ（Firefox 系など）と推定前は 30。「評価区間」の欄で手で直せ、動画ごとに覚える。欄には今のフレーム番号と、値が仮・推定・手入力のどれかを出す。
  - 「今の時刻を開始／終了にする」は、今表示しているフレームの始まり（フレーム番号÷フレームレート）に揃える。書き出しの `meta.frame_rate` と操作ログの `fps` に、使ったフレームレートを残す。
- **見返し**（ヘッダーの「見返し」または V キー）：評価し終えた記録を、止まらずに再生しながら追う。画面（平面の点・レバー・スライダーなど）は記録済みの値を映す。
  - 見返しの間は値を変えない：書き込み・記録オン・区間の値・変化の入力・グラフの編集・声の入力を止め、入力面は操作できない（薄く表示）。方式のキー入力とジョイスティック・スライダーの値も渡さない。
  - 聴いてから入力がオンでも、区間の終わりで止まらない。Space・←→・ボタン0（再生／停止）だけが効く。もう一度押すと戻る。操作ログに `review`（on／off）を残す。
- **記録オフでの操作**：スライダー・レバー・RankTrace（CARMA・スロットル・RankTrace・カスタムのキーボード／ゲームパッド、スライダーの機器）は、記録オフでも動かせる。記録オンにすると、動かした位置から記録が始まる。記録オフのまま再生やシークで時刻が動いたときは、記録済みの値に追従する。
- **コントローラー（ゲームパッド）**：ジョイスティック・スライダーの機器（自作の基板など）を Gamepad API で読む。機器のボタンを押すとブラウザが認識する。
  - 機器との約束（ツール側で決め打ち。基板側がこれに合わせる）：

    | 入力 | 内容 | 値 |
    |---|---|---|
    | 軸0 | ジョイスティックの横（右＝＋） | −1〜1・中心0。横軸の値 = 5 + x×4 |
    | 軸1 | ジョイスティックの縦（Gamepad API のとおり下＝＋。ツールの中で符号を反転し、上＝値が高い） | −1〜1・中心0。縦軸の値 = 5 − 軸1×4 |
    | 軸2 | スライダー1（+1＝上＝値が高い） | −1→1、+1→9 の線形（値 = 5 + 軸2×4） |
    | 軸3 | スライダー2（同上） | 同上 |
    | ボタン0 | 記録のオン／オフ（押した瞬間に切り替え。記録オン（R）の方式のとき） | |

    スライダーの物理的な向きは「+1＝上（奥）」と定義する。基板側は、スライダーを上（奥）に動かしたときに +1 になるよう出力する。ジョイスティックの遊びは 0.08（その内側は中心）。
  - **M5Stack の機器**（`firmware/atoms3_pad/atoms3_pad.ino`）：AtomS3 Lite に Grove Hub（U006）・Unit Joystick2（U024-C）・PbHub v1.1（U041）・Unit Fader（U123）×2 をつなぎ、上の約束どおりの USB ゲームパッド（名前 `AH Annotator Pad (AtomS3)`）にする。アノテータ側の変更は要らない。
    - 配線：本体の Grove → Grove Hub。Grove Hub の残りの口に Joystick2 と PbHub（I2C の口）を挿す。Fader の1本目を PbHub の CH0、2本目を CH1 に挿す（どれも Grove の線のまま。Fader は白＝位置の電圧・黄＝LED で、PbHub は各チャネルの白〔IO0〕でアナログ値を読む。LED は使わない）。I2C の番地は Joystick2＝0x63、PbHub＝0x61。フェーダーが1本なら、スケッチの `FADER_CH` の2本目を `-1` にする。
    - 書き込み：Arduino IDE にボードマネージャで `esp32`（Espressif、2.0.11 で確認）を入れ、ボード「M5Stack-ATOMS3」、Tools の USB Mode「USB-OTG (TinyUSB)」、USB CDC On Boot「Enabled」を選んで書き込む。一度書き込むと USB がゲームパッドになるため、次から書き込むときは本体のリセットボタンを緑の LED が点くまで（約2秒）押して離し、書き込みモードにしてから書き込む。
    - 本体の画面ボタン＝ボタン0（記録）。ボタンは 20 ms 続いた状態だけを送る（チャタリングで記録がオン・オフを繰り返さないように）。スティックの押し込みは、強く倒すと入りやすく値も揺れるので既定では記録に使わない（スケッチの `STICK_PRESS_RECORDS` を `true` にすると使う）。本体の LED は緑＝Joystick2 と PbHub の両方あり、黄＝片方だけ、赤＝どちらも見つからない（抜き差しすると1秒以内に戻る）。シリアルモニタ（115200）に読み値（`fails`＝スティックの読み取りに失敗した回数）を出す。I2C は番地を書いたら一度 STOP を出してから読む（Joystick2・PbHub は STOP を受けて送る値を用意するため、STOP なしで続けて読むと前に読んだ値が返り、スティックが一瞬中立に戻ったりボタンが押されたことになったりした）。スティックの読み取りが一度失敗しただけなら前の値を保ち、100 ms 続けて失敗したら外れたとみなして中立にする（一瞬だけ中立に戻らないように）。
    - 向きの確認：「設定」の「コントローラー」で軸のバーを見て、スティックを右に倒すと軸0が＋、手前に倒すと軸1が＋、フェーダーを奥に動かすと軸2・3が＋になるか確かめる。逆ならスケッチの `INVERT_STICK_X`・`INVERT_STICK_Y`・`INVERT_FADER` を `true` にして書き直す。フェーダーを端まで動かしても ±1 に届かないときは、シリアルモニタの `raw` を見て `FADER_MIN`・`FADER_MAX` を合わせる。
    - スライダー2 は HID の Rz と Rx の両方に送る（ブラウザが軸をどちらの順に並べても軸3になるように）。そのため軸は6本見え、軸4か軸5にも同じ値が出る。
  - **ジョイスティック**：EMuJoy・RCEA・FEELTRACE・DARMA・HaloLight・カスタム（インタフェース＝平面・円、入力＝マウスまたはゲームパッド）で使える。スティックの位置がそのまま値（円の方式は円の外を円周に吸着）で、離すと（遊びの中）中性 5・5。画面の点もスティックに合わせて動く。マウスもそのまま使え、スティックが遊びの外に出ている間はスティックが優先、遊びの中ならマウス（押している間）。
    - 記録：マウスだけのときは「押している間だけ記録」（hold）だが、ジョイスティックが使える（つながっていて「ジョイスティックを使う」がオン）間は「記録オン（R またはボタン0）の間だけ記録」（armed）になり、ヘッダーに記録ボタンが出る。記録オフの間もスティックで点は動き、記録オンにするとその位置から記録する。記録オンのまま機器を外すと記録オフになり、押している間の記録に戻る。
    - DARMA は以前から記録オンの間の記録で、読み取りだけを共通の仕組みに寄せた（マウスで押している間はマウスの位置、離すと中性）。
  - **スライダー**：スロットル（1本目＝横軸、2本目＝縦軸）・CARMA（評価している軸の回に1本目）・カスタム（インタフェース＝スライダー、尺度＝絶対・連続。2軸なら1本目＝横軸・2本目＝縦軸、1軸なら1本目）で使える。スライダーの位置がそのまま値（速度方式ではなく位置方式。スロットルの以前のゲームパッド操作〔スティックを倒している間レバーが動く〕は、これに置き換えた）。
    - 優先：スライダーを動かすと（揺れ 0.02 を超えたら）その軸はスライダーのものになり、以後スライダーの位置を値にする。キー（またはマウスのドラッグ）で動かすとキーが優先になり、またスライダーを動かすとスライダーに戻る（最後に動かしたものが優先）。
    - 記録オフの間もスライダーを動かせば表示が動き、その位置に留まる（記録はされない）。記録オンにするとその位置から記録する。記録済みの値への追従（シーク・記録オフに戻したとき）はスライダーを手放して行い、次にスライダーを動かすとまたスライダーの位置になる。
    - RankTrace（上下限なし・相対）とカスタムの相対尺度はスライダーの対象外（そのままホイール）。カスタムでマウスを選んでいても、スライダーの機器が使える間は記録オン（R）の間の記録になり、マウスはドラッグで動かす。
  - **AffectRank とジョイスティック**：AffectRank とカスタムの8方向ボタンは、変化の方向へスティックを大きく倒す（中心からの距離 0.7 以上）と、いちばん近い方向が1回入る。倒したままでは続けて入らず、中央付近（0.3 未満）に戻してから次を入れる。`_ranks.csv` の `source` が gamepad（クリック・テンキーは input）。
  - **RankTrace とジョイスティック**：RankTrace はジョイスティックの縦（上＝＋）で入れられる。上下限がないので位置ではなく速さ（倒し切ると1秒に2、↑/↓ キーと同じ）で、倒した量に応じて値が動き、離す（遊びの中）とその値に留まる。記録は今までどおり記録オン（R またはボタン0）の間。スティックで動かした値の書き込みは `source=gamepad`、ホイール・キーで動かした値は `input`。
  - **四角の平面ではスティックを角まで届かせる**（「設定」の「コントローラー」、既定オン）：スティックの可動域は円なので、斜めに倒し切っても横・縦はそれぞれ約 0.71 にしかならず、四角の平面の角（9・9 など）に届かない。四角の平面（EMuJoy・DARMA・HaloLight・カスタムの四角）では、方向はそのままで、倒した量（中心からの距離、1 で頭打ち）が四角の縁までの割合になるよう広げる（斜めに倒し切ると角、真横に倒し切ると辺の真ん中）。斜めの方向では、同じ倒し方でも値が中心から離れる。円の方式（RCEA・FEELTRACE・カスタムの円）には効かない。操作ログに `pad_square`、書き出しの `meta.display.pad_square` に残す。
  - **複数の機器**：`navigator.getGamepads()` の全機器を見る。ジョイスティック（軸0・1）とスライダー（軸2・3）は別々の機器でもよい。どの機器を使うかは「設定」で選べ（既定は自動）、自動のときは次の規則：
    1. 最初は、ジョイスティック＝最初の機器（番号の小さいもの）、スライダー＝軸を4本以上持つ最初の機器（なければ3本以上）。機器が1台ならその機器を両方に使う。
    2. 別の機器のスティックを大きく倒す（軸0か1が 0.5 を超える）と、ジョイスティックをその機器に切り替える（今のジョイスティックを倒している間は切り替えない）。
    3. 別の機器のスライダーを動かす（軸2か3が前の値から 0.2 を超えて動く）と、スライダーをその機器に切り替える。
    4. ボタン0 は、ジョイスティックかスライダーに使っている機器のどれで押しても効く。
  - 「設定」の「コントローラー」：「ジョイスティックを使う」「スライダーを使う」（既定オン。オフならつながっていても無視）と使う機器（自動か機器名）を選ぶ。どれもブラウザに保存する（`ahann_pad_joy`・`ahann_pad_slider`＝`1`/`0`、`ahann_pad_joydev`・`ahann_pad_sliderdev`＝機器名、空＝自動）。つながっている機器の名前（`gamepad.id`）と、何に使っているか、全部の軸の今の値（バーと数値）、ボタンの状態を表示する（パネルを開いている間だけ更新）。機器がないときは「接続されていません（機器のボタンを押すと認識されます）」。
  - 記録：機器で入れた値を1つでも含む書き込みは `_strokes` の `source=gamepad`（マウス・キーは `input`、グラフは `graph`）で、`_session.json` の各書き込みに `pad`（役割ごとの機器名 `{ joy, slider }`）が付く。操作ログに `pad_connect`・`pad_disconnect`（value＝機器名）、`pad_assign`（使う機器が変わった）、`pad_setting`（設定の変更）を残す。セッションの始めにも、つながっている機器を `pad_connect`（detail に `at_start`）で残す。書き出しの `meta.gamepads` に設定・使った機器名を残す。
- **動画の音声の F0**：動画を開くと、その音声（体験者の「あ」）から F0（声の高さ）をブラウザの中で計算する（YIN。16kHz・モノラルにして窓40ms・10msごと、70〜1000Hz。小さすぎる音と声の高さがはっきりしない区間は声なし）。評価グラフの3段目に動画全体の曲線と再生位置（縦軸は対数、範囲はその動画の F0 の分布から）、ツールの列の上に今の F0（Hz）とメーターを出す。F0 を見せるかは評価の条件に関わるので、「設定」の「動画の音声の F0 を表示する」で切り替えられ（既定オン、ブラウザに保存）、操作ログに `f0_display` を残す。書き出しの `meta.f0.shown` にも記録する。
- **声による入力**（ヘッダーの「音声」）：声で値を入れる（マイクの許可が必要）。認識のしかたは「設定」の「声の認識」で選ぶ。聞き取った文の解釈（下の言い方・補正）はどちらでも同じ。
  - **Chrome の音声認識**：Web Speech API。Chrome・Edge のみ。音声は Google などのサーバーに送られて認識される（ネット接続が必要）。
  - **Vosk**：PC の中で認識する（vosk-browser、`vendor/vosk.js`）。Chrome・Firefox（Zen など）で使える。音声は PC の外に出ず、ネット接続も要らない。「聞き取る語を限定する」をオンにすると、快度・覚醒度・数字・秒・再生・停止だけを聞き取る（聞き間違いが減る見込み。オフと比べられる）。
    - モデルの用意：`npm run vosk-model` で公式の日本語モデル（vosk-model-small-ja-0.22、約50MB）をダウンロードし、`models/vosk-model-small-ja-0.22.tar.gz` に作り直す（ダウンロード済みの zip があれば `npm run vosk-model -- <zip>`）。
    - 初回：「設定」→ 声の認識「Vosk」→「モデルを選ぶ」で `.tar.gz` を選ぶ。ブラウザ（IndexedDB）に保存されるので、次からは選ばなくてよい（「保存したモデルを消す」で消せる）。読み込みには数十秒かかることがある。
    - Chrome の音声認識がないブラウザ（Firefox 系）では、自動で Vosk になる。
    - 数の聞き直し（語を限定するとき）：Vosk は「十五」「三十八」のような数を [unk]（聞き取れない語）に取りやすく、「 秒 快 度 よん」のように時刻の数が落ちる。そこで、「秒」「分」の直前に数が無いときと、「度」の直後が [unk] のときは、その部分の音だけを数の語に限った2つ目の認識器で聞き直して数を補う（操作ログに `voice_refix`。value＝補った文、detail＝元の文）。同梱の vosk-browser 0.0.8 の文法は語の並びを縛れない（句を渡しても語ごとに自由に並ぶ）ため、この方法にしている。
    - マイクの雑音抑制・エコー除去は切っている（発話の頭が削られて最初の数が落ちやすいため）。音量の自動調整は使う。
    - 読み仮名の数（「じゅう ご 秒」「に じゅう よん 秒」）と、数だけの発話（「なな さん」「七 三」）も読む。
  - 言い方：「快度7」「覚醒度3」「快度7 覚醒度3」、または数字2つ「7 3」（快度・覚醒度の順）。漢数字・読み（なな・しち など）・全角数字も可。10 などの2桁や範囲外は値にしない。1軸ずつ評価する方式（CARMA・RankTrace の回、カスタムの1軸）では数字1つでも入る。「再生」「停止」でも操作できる。
  - 時刻を言うこともできる：「12秒 快度7」「1分5秒 7 3」「十二秒、覚醒度三」。「15秒」で区切ってから3秒以内に「快度4」と続けても、その時刻に入る（時刻だけの発話は履歴に「15秒（続けて値を）」と出る）。言った時刻は評価区間の「列の表記」と同じ読み方をする（カウントダウン＝残り秒。12秒の動画で「3秒」なら動画の8秒。経過＝評価区間の開始からの秒）。言った時刻が評価区間の外なら入らない。時刻を言わなければ下のとおり。
  - 値は話し始めた時刻（最初の途中結果が届いた時点の動画時刻）に入る。連続の方式は変化点、区間の方式はその区間の値（評価区間の外は入らない）。相対の方式（AffectRank・RankTrace）では値を入れない。
  - 聞き間違いの補正：認識の候補を最大5つ受け取り、値として読めた最初の候補を使う。化けやすい語を読み替える辞書を持つ（「街道」「開度」→快度、「学生」「拡声」→覚醒度。軸の語の直後なら「急」「球」→9、「録」→6 など。辞書は `core/voice.js` の `ALIAS`・`READ`）。対応している Chrome では「快度」「覚醒度」を認識の優先語にする。「設定」パネルに聞き取りの履歴（最新10件、聞き取った文と解釈）を表示する。
  - 操作ログに `voice`（オン／オフ）、`voice_heard`（聞き取った文と解釈・時刻）、`voice_input`（入った値）を残す。取り消し（Ctrl+Z）もできる。
- **色の設定**：「設定」の色の欄で、4象限（四隅）と4軸方向（上下左右）の色を変えられる。軸方向は「自動」（両隣の象限の中間）にもできる。グラデーションはこの8色の間を補間する。RCEA・HaloLight・FEELTRACE・カスタム（位置の色・画面枠の色）で使う。設定はブラウザに保存し、操作ログの `colors` と書き出しのメタ情報（`meta.colors`）に残る。
- **評価の軸の組**（「設定」の「評価の軸」）：Yik, Russell & Barrett（1999）の Figure 1 にある構造から、VA（Russell：快度・覚醒度。既定）・PANA（Watson & Tellegen：横＝ポジティブ〔PA〕、縦＝ネガティブ〔NA〕）・Thayer（横＝エネルギー、縦＝緊張）を選べる。値の持ち方（横軸・縦軸それぞれ1〜9、5が中立）は同じで、軸の名前・両端のラベル・方式の説明文・色の欄のラベル・書き出しの列名（`pa`・`na`、`energy`・`tension`）・声の入力の語（「ポジティブ7」「負の感情3」「エネルギー6」「緊張4」など）だけが変わる。色と象限の対応は変えない。
  - PANA・Thayer は VA の円環を 45° 回した軸なので、`_60hz.csv`・`_bins.csv` に VA に直した値 `va_valence = 5 + (x−y)/√2`、`va_arousal = 5 + (x+y)/√2`（x, y は横軸・縦軸の中立 5 からのずれ）も付ける。範囲は 1〜9 を少しはみ出すことがある（例：ポジティブ 9・ネガティブ 1 → 快度 10.66）。
  - SAM・Affect Grid・FEELTRACE・AffectRank は、絵や感情語が VA を前提にしているので VA のまま（Excel は感情ラベルの表を VA のときだけ出す）。選んだ軸の組は操作ログの `axes` と書き出しの `meta.axes` に残る。評価の途中で変えるときは確認を出す。
- **軸の順番**：快度、覚醒度の順で統一。値の範囲は1〜9（上下限なしの相対尺度を除く）。
- **参加者IDの変更**：動画を開いた後に参加者IDを変えると、この動画の保存データ（全方式分）を新しいIDへ移す。移し先に保存データがあれば確認し、キャンセルするとIDを元に戻す。操作ログに `participant_change` を残す。
- **方式の切り替え**：評価の途中でも切り替えられる。切り替える前の評価は自動保存され、同じ方式に戻すと続きから再開できる。自動保存は「方式＋参加者ID＋動画名」ごと。
- **評価区間**：ヘッダーの「評価区間」で、動画の時刻とは別に設定する。
  - 開始・終了：動画の時刻で指定する。「今の時刻を開始にする」「今の時刻を終了にする」「動画の終わりまで」でも設定できる
  - 区間の数、1区間の長さ（秒）。開始・終了・区間の長さを変えると区間の数を、区間の数を変えると終了を合わせ直す（終了は区間の区切りに揃える）
  - 評価区間は動画ごとにブラウザに覚える。ファイル名に加えてファイルの大きさ＋長さでも覚えるので、動画の名前を変えたり別の場所へ移したりしても復元する（名前で見つかればそれを優先）。参加者ID・入力方式が違っても、同じ動画を開けば同じ区間になる（操作ログに `range_restore`）
  - 列の表記：カウントダウン（残り）か経過
  - 区間方式（Excel・Affect Grid・SAM・カスタムの区間ごと）はこの区間ごとに値を1つ入力する。連続方式でも、書き出しの `_bins.csv` はこの区間で集計する。
  - 評価区間の外はグラフ上で薄く表示する。グラフには快度と覚醒度の欄の区切り線を引く。
  - 区間方式（Affect Grid・SAM・カスタムの区間ごと）では、評価区間の外の時刻では入力できない（案内を表示し、操作ログに `input_out_of_range` を残す）。動画の末尾で止まっている場合は最後の区間に入る。
- **練習モード**：動画を開く前でも各ツールを操作できる（値は画面上で動くだけ）。動画を開いた時点で練習中の入力と記録オンの状態は消え、そこから記録が始まる。
- **画面の配置**：ページはスクロールせず、ウィンドウの高さに収まるように組む（ヘッダー1段＋動画｜ツールの2列＋区間方式の欄＋評価グラフ）。入力面（平面・スライダー・SAMの絵など）は空いている高さに合わせて大きさが決まる。
  - **動画を別窓へ**：動画だけを別ウィンドウに出す（ノートPCで評価し、動画はモニターに出す使い方）。別ウィンドウはモニターへドラッグし、ダブルクリックで全画面。別ウィンドウを選んでいてもキー操作は評価側に届く。閉じるか「動画を戻す」で元に戻る。Chrome・Edge・Firefox 系（Zen など）で動く。操作ログの `video_window` に残る。
  - **グラフ**：評価グラフの開閉（既定は閉じる。状態はブラウザに保存）。
  - **設定**：動画の大きさ（25〜80％）、再生速度、グラフをなぞって編集するか、小窓（ピクチャーインピクチャー）。Firefox 系では小窓はブラウザの機能で開く（動画を右クリック →「ピクチャーインピクチャー」、または `Ctrl+Shift+]`）ので、案内に従って動画欄をたたむ。小窓の出し入れは操作ログの `pip` に残る。
  - **？**：操作の説明（方式ごとの説明を含む）。
- **グラフでの直接編集**：「グラフで編集」がオンのとき、下のグラフの快度・覚醒度の欄をなぞると値を描き換えられる。
  - 連続方式：なぞった時間範囲の値を描き換え、その直後は元の値に戻す。
  - 区間方式：なぞった区間の値を設定する。
  - 下端の目盛りの帯はシーク用。オフにするとグラフ全体がシーク用になる（実験で操作をそろえたい場合）。
  - グラフでの編集は `_strokes.csv` の `source=graph` と、操作ログの `graph_draw` / `graph_cells` に残る。

### 書き出し形式（CSV列）の仕様

- ファイル名は `<参加者ID>_<動画名（拡張子なし）>_<方式id><接尾辞>`。参加者IDが空なら `noid`。
- 文字コードは UTF-8（BOM つき）、改行は LF。`"`・`,`・改行を含む値は `"` で囲む（中の `"` は `""`）。
- 軸の値は 1〜9（上下限なしの方式は任意の実数）。未入力は空欄。
- 「区間」は評価区間（ヘッダーの「評価区間」）の区間。どのファイルも `bin`（0始まりの番号）・`label`（列の表記：カウントダウンか経過）・`t_start`・`t_end`（動画の秒、小数3桁）で始まる。

| ファイル | 列 | 内容 |
|---|---|---|
| `_60hz.csv` | `frame, t, valence, arousal` | frame＝0〜floor(動画の長さ×60)、t＝frame/60（小数4桁）。値は直前の変化点の値（階段状） |
| `_bins.csv`（整数値の連続方式：変化点キー、カスタムの9段階×連続） | `bin, label, t_start, t_end, valence, arousal` | 区間内の60Hzの値で最も長く続いた値（同数なら先に現れた値） |
| `_bins.csv`（連続値・上下限あり） | `…, valence_mean, arousal_mean, valence_r9, arousal_r9` | 区間内の60Hzの値の平均（小数3桁）と、それを四捨五入した9段階 |
| `_bins.csv`（連続値・上下限なし：RankTrace、カスタムの相対尺度） | `…, valence_mean, arousal_mean` | 区間内の平均 |
| `_bins.csv`（区間方式：Excel・Affect Grid・SAM・カスタムの区間ごと） | `…, valence, arousal` | 入力値（未入力は空欄） |
| `_bins.csv`（AffectRank・変化ボタン） | `…, n_changes, sum_d_valence, sum_d_arousal` | 区間内の変化の回数と、方向（−1/0/+1）の合計 |
| `_changepoints.csv` | `axis, t, value, initial` | axis＝valence／arousal。initial＝1 は t=0 の初期値の点 |
| `_strokes.csv`（書き込みが1回以上あるとき） | `stroke, source, axes, t, valence, arousal` | stroke＝書き込みの番号、source＝input（マウス・キーの入力）／gamepad（ジョイスティック・スライダーの機器の値を含む書き込み）／graph（グラフで編集）、axes＝v・a・va。書き込んでいない軸は空欄 |
| `_ranks.csv` | `t, label, d_valence, d_arousal, source` | 変化の入力の時刻・方向の名前・方向（−1/0/+1）・入れ方（input＝クリック・キー、gamepad＝ジョイスティック） |
| `_events.csv` | `wall_ms, video_t, type, axis, value, detail` | wall_ms＝セッション開始からの経過ミリ秒（復元したときは続きから）、video_t＝そのときの動画の秒 |

`_events.csv` の `type`：`session_start`・`restore`・`mode_switch`・`play`・`pause`・`seek`（detail＝移動前の時刻）・`ended`・`rate`・`range`・`option`・`graph_edit`・`pip`・`export`・`undo`・`arm`／`disarm`・`input`／`input_same`（変化点キーなど）・`click`（一時停止中のクリック）・`delete`・`stroke`（detail＝区間・サンプル数・終わった理由）・`graph_draw`／`graph_cells`・`cell_input`／`cell_clear`／`cell_grid`／`cell_sam`／`cell_custom`（区間の値）・`cell_focus`・`memo`・`rank`（AffectRank）・`pad_connect`／`pad_disconnect`（value＝機器名、detail＝番号・軸とボタンの数）・`pad_assign`（ジョイスティック・スライダーに使う機器が変わった）・`pad_setting`（コントローラーの設定）・`listen_mode`（聴いてから入力の設定）・`listen_pause`（区間の終わりで止まった。detail＝区間）・`listen_record`／`listen_record_end`（区間を再生し直して記録した始めと終わり）・`listen_replay`（R でもう一度聴いた）・`review`（見返しの on／off）・`reset`（入力をすべて消した）・`redo`（やり直し）・`grid_display`（区切りの線）・`pad_square`（スティックを四角に広げる）・`fps`（フレームレートの推定・手入力）。

`_session.json` は `{ meta, data, log }`。`meta` は参加者ID・動画名・長さ・開始時刻・ツールの版（`ah-annotator-v0.5`）・方式・方式の設定・評価区間・色の設定（`colors`）・聴いてから入力で評価したか（`listen`：`on`）・ゲームパッド（`gamepads`：`use`＝使うか、`device`＝選んだ機器か auto、`joystick`・`slider`＝書き出した時点で使っている機器名、`connected`＝つながっている機器、`used`＝書き込みに使った機器 `{ role: joy|slider, id }`）、`data` は変化点（`points`）・書き込み（`strokes`。機器で入れたものは `source: 'gamepad'` と `pad`）・区間の値（`cells`）・相対の変化（`events`）・メモ、`log` は `_events.csv` と同じ内容。

自動保存は localStorage のキー `ahann4:<方式id>:<参加者ID>:<動画名>` に `{ meta, data, log, undo（直近10回分） }` を入れる。「動画の大きさ」の設定は `ahann_vidsize`。

## カスタム方式（設計軸の組み合わせ）

入力方式「カスタム」では、次の設計軸を自由に組み合わせられる。先行研究にない組み合わせ（SAMの絵×時間連続、四角平面×区間ごと、グリッド×1軸ずつ、など）も作れる。設定欄の下に、今の組み合わせがどのプリセットに相当するか（該当しなければ「プリセットに該当しない組み合わせ」）を表示する。

| 設計軸 | 選択肢 |
|---|---|
| インタフェース | 四角平面／円／9×9グリッド／SAMの絵／1〜9ボタン／スライダー2本／8方向ボタン（変化の方向） |
| 時間 | 連続（時刻に書き込む）／区間ごと（評価区間に従う）。8方向ボタンでは選ばない（変化の時点） |
| 値 | 連続（1〜9 の小数）／離散（1〜9 の整数）。平面・円・スライダーで選ぶ。グリッド・SAM・ボタン・8方向ボタンは離散だけ、相対尺度は連続だけ |
| 入力 | マウス／キーボード／ゲームパッド（9段階のインタフェースと区間ごとでは、マウスとキーボード（数字）のみ。8方向ボタンはマウスとテンキー） |
| 次元 | 2軸同時／快度のみ／覚醒度のみ（1軸ずつの回）。1軸のとき、もう片方の軸は 5 に固定する（画面の点も 5 の線上だけを動く。記録はしない）。8方向ボタンでは、その軸だけが変わる2方向になる |
| 尺度 | 絶対（1〜9）／相対（上下限なし。スライダー×連続のときのみ） |
| フィードバック | 顔／軌跡／位置の色／画面枠の色 |

書き込み方法は組み合わせで決まる。

- 9段階のインタフェース（グリッド・SAM・ボタン）×連続：クリックまたは数字キーで、その時刻に変化点を置く。
- 平面・円・スライダー×連続×マウス：押している間だけ書き込む。値が「離散」なら書き込む値を整数に揃える。
- 平面・円・スライダー×連続×キーボード／ゲームパッド：記録オン（R）の間だけ書き込む。相対尺度でマウスを選んだ場合はホイールで操作する。ゲームパッドは、平面・円ならジョイスティック（位置＝値、離すと中性）、スライダーならスライダーの機器（位置＝値）。
- 平面・円・スライダー×連続×マウスでも、ジョイスティック（平面・円）またはスライダーの機器（スライダー・絶対）が使える間は、記録オン（R）の間だけ書き込む（「コントローラー」）。
- 区間ごと：どのインタフェースでも、今の区間の値を設定する（値が「連続」なら小数、「離散」なら整数）。
- 8方向ボタン：変化を感じたときだけ方向を選ぶ（AffectRank と同じ。相対イベントモデル、書き出しは `_ranks.csv`）。
- 軌跡（フィードバック）は、実際に評価した範囲だけを描く。書き込み中はその書き始めから、再生だけのときは最初に記録した時刻から（書き始める前の値＝初期値 5・5 などから線を引かない）。

プリセット（EMuJoy、FEELTRACE、RCEA、DARMA、スロットル、CARMA、RankTrace、変化点キー、Affect Grid、SAM、AffectRank に相当する組み合わせ）から読み込んで、そこから1軸だけ変えることもできる。専用の方式との違いとして、FEELTRACEの感情語、RCEAの動画上ジョイスティック、HaloLightの円、RankTraceの軌跡全体表示はカスタム方式には入れていない。
