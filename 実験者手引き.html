あアラウド 評価ツール　実験者のための手引き

評価ツールで実験を行う手順：準備から結果の回収まで

この手引きは、評価ツールの実験モードで実験を行う人のためのものである。実験フォルダの準備、当日の進め方、結果の回収、トラブルへの対処を順に説明する。発声者側（録画をすぐ本人が評価する）と分析者側（用意した動画を評価する）で違う所は、タブで分けてある。参加者に見せる操作は、別紙「評価ツールの使い方」（評価者マニュアル.html）にまとめてある。

第1部

準備

SECTION 1

実験の全体像

実験者が「実験フォルダ」を開いて参加者を選ぶと、決めておいた順で試行が進む。1 試行は「開始」から「完了」までで、完了するたびに結果が 1 つの zip として保存される。

用語

  • 実験フォルダ：設定ファイルと動画を入れたフォルダ。実験の内容はすべてこのフォルダで決まる。
  • 試行：1 本の動画（または録画）を 1 つの方式で評価する 1 回分。練習の試行と本番の試行がある。
  • 録画の試行：発声者が課題をしている様子をその場で録画し、直後に本人が評価する試行。評価する録画は実験者がその場で選ぶ。
プレイを録画するOBS など外のソフト → 録画を選び区間を合わせる実験者 → 「参加者に渡す」実験者 → 「開始」〜「完了」発声者が評価する → 「次へ」次のプレイへ

プレイと評価を交互に繰り返す。評価する録画は試行ごとに実験者が選ぶので、フォルダに動画を入れておく必要は無い。

参加者を選ぶ実験者 → 「開始」〜「完了」分析者が評価する → アンケートあれば → 「次へ」次の動画へ

評価する動画と評価する範囲は、すべて実験フォルダに用意しておく。当日の実験者の操作は、最初に参加者を選ぶことだけである。

SECTION 2

実験フォルダを用意する

実験フォルダには、試行の順を決める experiment.json と、画面の設定と評価区間を決める setup.json を入れる。前者は Claude に頼んで作り、後者は通常の画面で書き出す。

実験フォルダ/
  experiment.json   試行の順・参加者・アンケート（Claude に頼んで作る）
  setup.json        実験中の画面の設定と、動画ごとの評価区間（通常の画面で書き出す）
  動画A.mp4 …       評価する動画（分析者側だけ）

experiment.json：試行の順を決める

このリポジトリで Claude Code に「実験の設定を作って」と頼む。方式、動画、参加者の数、アンケートの URL を聞かれるので答える。順序のカウンターバランスを組み、誤りが無くなるまで検査したファイルができる。参加者を足すときも「参加者を足して」と頼めばよい。

  • 本番の参加者が 1 人ずつ来る実験でも、全員を 1 つのファイルに書く。当日は来た人の ID を選ぶ。
  • アンケート（Google フォームなど）を試行ごと・最後に開かせることができる。回答と参加者を結び付けるため、事前入力の URL を用意して Claude に渡す。

setup.json：画面の設定と評価区間を決める

録画の試行だけなら、評価区間は当日に実験者が合わせるので、setup.json は画面の設定のためだけに使う。無くても実験は始められるが、画面の設定をそろえるため置くことを勧める。

  1. 実験フォルダに experiment.json を入れておく。
  2. ツール（index.html）を開き、「設定」→「実験用の設定を書き出す」で実験フォルダを選ぶ。
  3. 「設定」と「実験中に出すボタン」の欄を選ぶ。
  4. 「setup.json を書き出す」を押し、ダウンロードされた setup.json を実験フォルダに入れる。

評価区間（評価する範囲と区切り）を動画ごとに決めておく。発声者の録画を使うときは、発声者が評価した区間をそのまま取り込める。

  1. 評価する動画を実験フォルダに入れる。
  2. 評価区間を決める。次のどちらかで行う。
    • 自分で合わせる：通常の画面で動画を 1 本ずつ開き、「評価区間」で開始・終了・区切りを合わせる。合わせた区間はブラウザに覚えられる。
    • 発声者の区間を使う：手順 3 の画面で「発声者の結果を取り込む」を押し、発声者側の実験で書き出された zip を選ぶ（複数を一度に選べる）。録画のファイル名で動画を探し、発声者の評価区間と区切りを当てる。
  3. 「設定」→「実験用の設定を書き出す」で実験フォルダを選ぶ。動画ごとの評価区間の一覧が出る。「未設定」の動画が無いことを確かめる。
  4. 「設定」と「実験中に出すボタン」の欄を選ぶ。
  5. 「setup.json を書き出す」を押し、ダウンロードされた setup.json を実験フォルダに入れる。
補足

発声者が声を出していない区間を、分析者が変えられない「発声なし」としてあらかじめ決めておくこともできる。setup.json の手直しが要るので、Claude に頼む。

注意

評価区間を直したら、setup.json を書き出し直して実験フォルダの古いものと入れ替える。フォルダにある setup.json の設定は、書き出し直しても初めの値として引き継がれる。

SECTION 3

実験用の PC を整える

ブラウザのダウンロード先を実験フォルダの中に変え、本番と同じ流れで 1 度通しておく。

  1. ブラウザ：Chrome か Edge を使う（Firefox 系でも動く）。ツールは index.html をブラウザで開くだけで動く。
  2. ダウンロード先：ブラウザの設定で、ダウンロード先を実験フォルダの中の results などに変える。ブラウザは結果を任意のフォルダへ保存できないので、結果はダウンロード先に入る。毎回保存先を尋ねる設定はオフにしておく。
  3. フォルダの検査：「設定」→「実験フォルダを開く」で実験フォルダを選び、参加者を選ぶ画面に誤りや「確かめてください」の警告が出ないかを確かめる。警告の意味が分からなければ Claude に聞く。
  4. リハーサル：試しの参加者 ID で 1 人分を通し、zip がダウンロード先に入ることを確かめる。試しの記録は、参加者を選ぶ画面の「この参加者の記録をブラウザから消す」で消しておく。
  5. 機器：録画のソフト（発声者側）、ヘッドホンやスピーカーの音量、画面の明るさを本番の状態にしておく。
補足

フォルダを選ぶ画面では、フォルダの中のファイルが表示されない。そのフォルダを選べば読み込める。エクスプローラーからフォルダをボタンに落としても開ける。

第2部

当日

SECTION 4

実験を始める

「実験フォルダを開く」でフォルダを選び、参加者と始める試行を選んで「実験を始める」を押す。

  1. ツール（index.html）を開く。
  2. 「設定」→「実験フォルダを開く」で実験フォルダを選ぶ。
  3. 「参加者」で来た人の ID を選ぶ。
  4. 「始める試行」を確かめる。終えた試行には「（済）」、途中で抜けた試行には「（途中）」が付き、ふつうは終えていない最初の試行が選ばれている。「（済）」の試行を選ぶと、やり直し方を選ぶ画面が出る（8 章「参加者が『完了』を早く押してしまった」）。
  5. 「実験を始める」を押す。

実験が始まると、参加者 ID、方式、「設定」、「？」、書き出しなどのボタンは画面から消える。参加者に見えるのは、再生の操作、進行（「2 / 4　練習」など）、「完了」と、設定で許したボタン（視聴、基準音声など）だけである。

注意

ID の選び間違いに気をつける。別の ID で始めると、その ID の試行として記録される。

SECTION 5

試行を進める

試行ごとに全画面の「開始」が出る。参加者が「開始」を押してから「完了」を押すまでが評価の時間として測られる。

試行に来ると「録画を選ぶ（実験者の方へ）」が出る。プレイを録り終えたら、次の順で操作する。

  1. 録画のソフトで録画を止める。
  2. 「録画した動画を選ぶ」で今の録画を選ぶ。どのフォルダのファイルでもよい。
  3. 画面の右上に「評価区間を合わせる（実験者）」の帯が出る。動画を動かし、プレイの始めで「今の時間を開始にする」、終わりで「今の時間を終了にする」を押す。Space で再生・停止、, . で 1 コマずつ動かせる。この間、参加者は値を入れられない。
  4. 基準の「あ」をプレイと別に録ったときは、帯の「基準音声の録画を選ぶ」でその録画を選ぶ。選んだ録画は、同じ参加者の後の録画の試行にも引き継がれる。
  5. 「参加者に渡す」を押す。再生位置が動画の最初に戻り、「開始」が出る。区間合わせの時間は評価の時間に入らない。
  6. 参加者が評価し、「完了」を押す。
補足

違う録画を選んだときは、帯の「動画を選び直す」で手順 2 に戻れる。練習の試行では、評価区間を録画の最初の 10 秒程度にすると時間を節約できる。

試行に来ると「開始」が出る。実験者の操作は無い。

  1. 参加者が「開始」を押して評価する。
  2. 評価を終えたら、参加者が「完了」を押す。
補足

「この試行を始められません」と出たときは、setup.json の評価区間が動画と合っていない。8 章を見る。

完了の後（共通）

  1. 「完了」を押すと確認が出て、OK でその試行の値が確定する。以後、参加者の画面では変えられない（実験者が試行をやり直すことはできる。8 章）。
  2. その試行の zip がダウンロード先に保存される。
  3. アンケートがある試行では「アンケートを開く」が出る。すべて押すまで「次へ」は出ない。
  4. 「次へ」で次の試行へ進む。最後の試行の後は「すべての試行が終わりました」と出る。やり直した試行の後は、終えた試行を飛ばして、終えていない次の試行へ進む。
注意

「開始」の画面が出ている間は、キー、マウス、ゲームパッドのボタンが評価に効かない。参加者が席に着いてから「開始」を押してもらう。

SECTION 6

終わった後

zip がそろっていることを確かめてから、ブラウザに残った記録を消す。

  1. ダウンロード先に、試行の数だけ zip があることを確かめる。やり直した試行には、前の zip と _redo の付いた zip の両方がある。どちらも消さずに保存する。
  2. 結果を実験の保存場所へ移す。
  3. Ctrl+Shift+E で実験モードを抜ける。もう一度「実験フォルダを開く」で開き、参加者を選んで「この参加者の記録をブラウザから消す」を押す。zip、進行、途中の自動保存がブラウザから消える。
注意

ブラウザの記録は、ファイルを確かめてから消す。消した後は「ブラウザに残っている結果」から書き出し直せない。

補足

最後の画面の「要約をもう一度書き出す」で、全試行の要約（_trials.csv）だけを書き出し直せる。

結果と困ったとき

SECTION 7

書き出される結果

1 試行につき zip が 1 つ保存される。最後の zip には、それまでの全試行の要約が入っている。

zip の名前は P01_t02_動画名_方式.zip の形である。t02 は試行の番号で、練習なら t01p のように p が付く。途中で抜けた試行は名前に _partial が付く。やり直した試行は _redo1（2 回目なら _redo2）が付き、前の zip とは別のファイルになる。

ファイル中身
_bins.csv評価区間の区間ごとの値。分析でいちばんよく使う。
_trials.csvその時点までの全試行の要約。評価にかかった時間（task_ms）、再生した時間、値を入れた区間の数などが 1 試行 1 行で入る。やり直した試行は、やり直しの回数（redo）、前の完了の時刻（prev_end_iso）、前の回までの時間（task_ms_prev）も入る。
_60hz.csv値を 60 Hz の系列にしたもの。連続の方式と比べるときに使う。
_events.csv再生、停止、入力、取り消しなど、すべての操作の記録。
_session.json上のすべてと実験の情報をまとめたもの。評価ツールの「読み込む」で開き直せる。
補足

やり直した試行は、_redo の数がいちばん大きい zip が最後の評価である。前の zip は、やり直す前の評価の記録として残す。

補足

列の意味を知りたいときは、Claude に「CSV のこの列は何？」と聞く。

SECTION 8

トラブルのとき

記録は試行ごとにブラウザにも残るので、ページを閉じたり読み込み直したりしても、多くの場合は続きから再開できる。

ページを読み込み直してしまった・ブラウザが落ちた

「実験フォルダを開く」でフォルダを選び直し、同じ参加者を選んで「実験を始める」を押す。終えていない最初の試行から始まる。途中だった試行は、続きから再開するかを尋ねられる。止まっていた間の時間は評価の時間に入らない。

録画の試行では「同じ録画を選び直してください」と出る。同じ録画を選べば区間合わせを飛ばして再開する。

試行の途中で実験をやめたい

Ctrl+Shift+E を押し、確認で OK を押す。その試行のそこまでの結果が _partial の付いた zip として保存され、通常の画面に戻る。

zip が保存されていない・消してしまった

実験フォルダを開き直し、参加者を選ぶ画面の「ブラウザに残っている結果」から「書き出す」（1 つずつ）か「すべて書き出す」を押す。

「前に選んだ録画と違います」と出た

再開のときに、前と名前か大きさが違う録画を選んだ。選び間違いなら「キャンセル」して正しい録画を選ぶ。

「この試行を始められません」と出た

評価区間の終わりが動画の長さを超えているなど、setup.json の評価区間に誤りがある。Ctrl+Shift+E で抜け、setup.json を書き出し直して（2 章）から実験フォルダを開き直す。

参加者が「完了」を早く押してしまった

やり直すかどうかは実験の計画に従って決める。やり直すときは次の手順で進める。前の zip は消えずに残り、やり直した回数と前の完了の時刻が記録に残る。

  1. Ctrl+Shift+E で実験モードを抜ける。次の試行の「開始」を押した後なら、その試行は途中として保存され、後で続きから再開できる。
  2. 「実験フォルダを開く」でフォルダを選び直し、参加者と、やり直す試行（「（済）」が付いている）を選んで「実験を始める」を押す。
  3. 実験者向けの画面が出る。試行の名前と完了した時刻を確かめ、次のどちらかを押す。
    • 前の評価を読み込んで直す：完了した評価（値、評価区間、参加者が自分で区切った区切り、区間内で変化の形）を戻す。
    • 空から評価し直す：値の無い状態から始める。
  4. 録画の試行では、同じ録画を選び直す。区間合わせは飛ばす。
  5. 参加者には、いつもの「開始」の画面が出る。参加者に渡して「開始」を押してもらう。
  6. 完了すると、名前に _redo1 が付いた zip が保存される。アンケートがある試行では、もう一度「アンケートを開く」が出る。
  7. 「次へ」を押すと、終えた試行を飛ばして、終えていない次の試行へ進む。残りが無ければ「すべての試行が終わりました」と出る。

「この試行の zip が残っていません」と出たとき：ブラウザの記録を消した後である。「ファイルを選ぶ」を押し、ダウンロード先の zip（やり直したことがあれば、_redo の数がいちばん大きいもの）か _session.json を選ぶ。参加者や試行の違うファイルを選ぶと確認が出るので、選び間違いなら「キャンセル」する。

別の PC で続けるとき：その PC には進行が残っていないので、「（済）」が付かない。参加者を選ぶ画面で「結果のファイルから試行をやり直す」を押し、その試行の zip を選ぶ。試行はファイルから決まる。

要約（_trials.csv）の task_ms などは、やり直した回だけを数える。前の回までの時間は task_ms_prev に入る。

SECTION 9

当日のチェックリスト

参加者が来る前、試行ごと、帰った後の 3 回に分けて確かめる。

参加者が来る前

  • ブラウザのダウンロード先が実験フォルダの中になっている。
  • 実験フォルダを開いて、誤りと警告が出ない。
  • 前の参加者や試しの記録がブラウザから消えている。
  • 録画のソフトと音の機器が動く（発声者側）。
  • 参加者に見せる「評価ツールの使い方」を用意してある。

試行ごと

  • 正しい録画を選び、区間をプレイの始めと終わりに合わせた（発声者側）。
  • 完了の後、zip がダウンロード先に増えた。
  • アンケートを開いてから「次へ」へ進んだ。

帰った後

  • 試行の数だけ zip がある（やり直した試行は _redo の zip もある）。
  • やり直した試行があれば、その旨（試行と理由）を実験の記録に書いた。
  • 結果を保存場所へ移した。
  • ファイルを確かめてから、その参加者の記録をブラウザから消した。
